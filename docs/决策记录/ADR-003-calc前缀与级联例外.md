# ADR-003 `calc_` 前缀与级联例外

状态:**已采纳**(2026-09-06 签字;两轮回填定稿,见文末「第二轮 / 第三轮」;变更需新开 ADR)
关联:架构 v2 §0 ⑩、§5.2、§10「命名规范」;计划 T1.3、T3.4

## 背景

原稿要求运算结果统一前缀并在规则链入口按前缀一刀切阻断,防回环。但现有多级归档(5 分钟 → 1 小时 → 1 天)与 4 分组 + 1 汇总的分层汇聚依赖「输出再触发」(processCfs);一刀切会把它们切断。既有站点已落库的遥测若改名会断裂。

## 决定(推荐)

1. **前缀只对新输出强制**:工具生成的每个新运算结果 key 形如 `calc_<name>`;向导 UI 自动加前缀,不允许手改前缀。
2. **级联例外走白名单**:规则链入口过滤节点逻辑为「originator 为 Asset 放行;originator 为 Device 且 key 以 `calc_` 开头 → 检查该 key 是否在白名单,在则放行、不在则丢弃」。白名单由编译器从 rollup / 分层汇聚配置**自动推导**(所有作为下一级输入的输出 key),不由人维护;写在规则链过滤节点的脚本常量里,并同步到站点资产属性 `calcCascadeKeys` 供排查。
3. **既有站点旧输出**:不改名。编译器为每个既有站点生成迁移表 `migrations/<site>.rename.json`(`{ old: 'PAvg5m', new: 'calc_PAvg5m', entity, since }`),一期只生成不执行;绑定选择器对旧 key 显示「未加前缀(旧)」标签但允许绑定。

## 备选与放弃理由

- **一刀切阻断**:切断级联 → 否。
- **不加前缀,只靠 originator 分流**:单设备派生值写回设备无法与原始 key 区分,页面上分不清原始 / 计算值 → 否。
- **立即为旧站点改名并迁移历史数据**:需要写 TB 时序表迁移,超出一期 → 二期。

## 对代码的直接影响

- `packages/compiler/src/core/`:`buildCf` 输出 key 加前缀;`rollupMetadata` 推导白名单并注入过滤节点脚本;新增 `migrations` 输出。
- `apps/deploy-tool` 第 3 步运算配置:输出名输入框显示不可编辑的 `calc_` 前缀。
- live 测试:级联链在白名单下仍触发(5 分钟 → 1 小时聚合有值)。

## 第二轮回填后的决定(2026-09-06)

- 同事的命名规则:资产名 `REALTIME_* / HIST_* / STAT_REALTIME_* / <站点>_STAT_REALTIME_*`,遥测 key 为 camelCase 加业务前缀(`ts* / hist* / metric* / forecast* / GFFD_* / CNXT_* …`,见 KEY 清单)。**`calc_` 与之不重叠,前缀方案定稿。**
- 归档服务全量采集所有遥测 key:`calc_*` 写成遥测就会被归档(可从 kz 取长曲线);写成**服务端属性不归档**。规则:要画曲线的结果写遥测;只作中间量 / 状态位的结果写属性。
- 规则链内没有「结果再触发别的计算」:白名单只服务工具自己的级联链。
- 既有站点旧输出「不改名 + 迁移表」的决定不变。

## 第三轮回填(2026-09-06)

高潮:「资产改网关 + key 加前缀」**两周前已完成**,规则「业务模块_原测点名」(如光伏 `GFFD_xxx`),为省级 / 站点区分。KEY 清单即现状,不存在待发生的改名;`calc_` 仍不重叠。本 ADR 无未决项。

## 落地(2026-09-06)
