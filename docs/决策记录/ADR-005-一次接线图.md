# ADR-005 一次接线图(SLD):图存哪、测点怎么绑、编辑器用什么

状态:**已采纳**(2026-09-18,YY 确认路线 B 与 §决定 各条;Spike A / B 结论与契约修订见后文)
关联:`docs/开发计划-接线图.md`(T5.x);取代开发计划 v2 的 T1.4 / `svg-diagram` 方案;依赖 ADR-002(实体按名存按 id 发)

## 背景

用户侧电力系统的一次接线图要在部署工具里画、绑 TB 测点,发布后嵌进同事前端 / 独立薄壳的页面槽位。要求易操作、易维护。三条路线(外部画图导入 SVG / 自研图元式编辑器 / 现成 SCADA 编辑器)比较后,YY 选定**自研图元式编辑器**:图是结构化数据,可校验、可批量改、带电气语义。

契约 v1 已冻结(2026-09-06):改字段要走 ADR + 双方签字,新增只能是可选项。所以本 ADR 的核心问题是:**怎么在不动契约 JSON Schema 的前提下,把一张几百个测点的图放进现有的「页面配置 → 发布 → 渲染」链路。**

## 决定

### D1 图随页面存

图(`SldDoc`)存在 `sld` 组件的 `props.doc`,随 `PageConfig` 一起发布到 `ScadaPage` 资产;不新建资产类型。`WidgetConfig.props` 在契约里本来就是自由对象。

代价:同一张图放两个页面要复制一份(YY 2026-09-18 接受)。

### D2 测点绑定放 `bindings`,用动态槽位名

测点绑定写在 `WidgetConfig.bindings['pt.<pointId>']`,图里只存对 `pointId` 的引用(开关状态来源、数值标签)。`pointId` 及图内一切 id 限定 `^[A-Za-z0-9_-]+$`。

为什么不把绑定放进图里:编译器 `eachBinding()` 遍历 `bindings` 的全部槽位做按名解析 id(ADR-002),工具的 key 存在性检查、声明 key 校验也都遍历 `bindings`;解析器不看注册表,未知槽位名照样订阅。绑定放这里,这些环节**零改动**自动覆盖;放进图里则每个环节都要另写一套遍历。

契约 JSON Schema 对 `bindings` 的 key 没有 pattern 限制,`pt.xxx` 合法。

### D3 告警只用一个静态槽位

`sld` 组件声明一个静态槽位 `alarms`(绑站点资产,靠 TB 告警上卷),组件内按告警 originator 匹配节点。不给每个节点单独绑告警——`LegacyDataSource` 的每条告警订阅是一个 10 秒 REST 轮询,300 个节点约 30 次请求 / 秒。

某站点没开告警上卷时的兜底:`alarms` 槽位允许多条绑定,按**设备数量级**绑,不按节点。

### D4 图里的实体只存名字

`SldNode.entity` 只有 `{ type, name }`。发布器的 `collectEntityRefs` 只看 `bindings` / `actions`,不看 `props`;图里放 id 换环境就失效。运行时需要节点的实体 id(告警匹配、点击事件)时,从该节点名下测点绑定的 `entity` 取。

### D5 注册表类型两处可选扩展

- `WidgetDefinition.dynamicSlots?: { prefix, title?, valueType, modes?, stamped? }[]`:槽位名以 `prefix` 开头即按该规格校验;只允许单个绑定。
- `PropSchema` 增加不透明对象 `{ type: 'object', format: 'sld-doc' }`:部署工具属性面板画成「编辑接线图」按钮。

注册表类型不进 JSON Schema(`schema/registry.ts` 文件头已写明),不触发契约变更流程。注:props 的 schema 校验只发生在部署工具(`editor/validate.ts`),渲染器不校验 props——契约 `page-config.ts` 注释里「渲染器按 propsSchema 校验」一句与实现不符,以实现为准。

### D6 渲染器运行时三处向后兼容扩展

1. **带时间戳的值**:`stamped: true` 的槽位,组件拿到 `{ v, ts }`,`ts` 是数据时间戳。**过期变灰按数据时间戳判**,不按到达时间(订阅首包给的是最新值,可能是几小时前的)。
2. **`widget-event` 透传**:组件 `emit('widget-event', { name, detail })`,`<ScadaPage>` / `<ScadaWidget>` / 放大层向外抛 `{ widgetId, type, name, detail }`。接线图的 `node-click` 走它。**这是宿主可见的 API 新增**(纯新增,不影响现有用法),需告知庄艳芹。
3. **设计态占位**:`sampleData(cfg?)` 带上组件配置,让 `sld` 能按自己的 `pt.*` 键出占位值(编辑器槽位缩略图用)。

### D7 运行时零依赖,编辑器用 AntV X6

运行时 `sld` 组件纯 Vue + SVG,不引入任何新依赖——同事宿主只升渲染器版本。编辑器用 AntV X6 3.x(MIT;3.1.8 于 2026-08-11 发版;`@antv/x6-vue-shape` 3.0.2 支持 Vue 3,其 `@vue/composition-api` 是可选 peer,实测未被自动安装),只装在 `apps/deploy-tool`。X6 被隔离在 `x6-adapter.ts` 与画布组件内,图的真相始终是 `SldDoc`,换库只重做画布。

### D8 图元一份定义、两处使用

`packages/renderer/src/sld/symbols/` 一图元一文件:SVG 片段 + 端口 + 导通方式 + 状态片段 + 默认标签位。`<SldSymbol>` 组件经包入口导出,运行时直接画,编辑器里的 X6 Vue 节点复用它 → 所见即所得。

图元硬约定:只用 `currentColor` 上色,颜色由运行时按带电 / 电压等级 / 告警决定;线宽统一;坐标、包围盒、端口全部落在栅格上。

### D9 纯逻辑集中在 model 层

`packages/renderer/src/sld/model/`:类型、几何(端口坐标、母线取点、连线折线)、测点引用收集、状态映射、结构校验、连通图与带电计算、复制间隔改绑、版本迁移。无 Vue、无 X6,可单测。

`doc` ↔ `bindings` 的一致性检查(图里引用的 `pt.*` 必须有绑定;没被引用的 `pt.*` 给提示)放部署工具 `editor/validate.ts`,**不进编译器**——编译器刻意零依赖、不依赖渲染器,放进去只能手抄一份 SldDoc 结构。

### D10 底图不发布

描摹底图 `doc.background` 只存项目文件,发布前由工具剥掉。data URL 会把页面撑到 MB 级,而发布器每次还把最近 10 版完整配置写进 `pageConfigHistory`。

### D11 带电着色纳入一期(YY 2026-09-18)

`energize(doc, symbols, states)`:从标了 `source` 的节点出发,沿连线 / 母线 / 导通的图元传播。

- 图元的 `conduct`:`always`(CT、熔断器、电缆头)/ `switch`(合位才通)/ `transformer`(能传,电压等级换成 `node.portKv[出口端口]`)/ `none`(负荷、PT、避雷器等终端)。
- 开关状态 `unknown`(没数据、映射不上、过期)**按断开算**,其后本可带电的部分标 `uncertain`,运行时用区别于「确定失电」的样式画——宁可提示不确定,不可把没数据画成带电。
- 母线自己给了 `kv` 的以母线为准;颜色按电压等级取(组件 props 可配),失电灰。

遥控分合闸一期不做(防误、二次确认、审计,单独立项)。

## 数据模型

`SldDoc` v1 见 `packages/renderer/src/sld/model/types.ts`(单一真相,此处不重复)。要点:节点 `{ id, symbol, x, y, rot, flip?, name?, entity?, state?, source?, portKv? }`;母线是水平 / 垂直线段;连线端点是「节点端口」或「母线 + 距 (x1,y1) 的整数距离 d」;标签分文字 / 数值两种,可依附节点。

## Spike B:TB WebSocket 单条消息上限(2026-09-18,CT110 只读实测)

`LegacyDataSource` 把同一 tick 的订阅合成**一条** WS 消息(首发与重连重放两处),同一实体的多个 key 也不合并。实测:

| 做法 | 消息大小 | 结果 |
|---|---|---|
| 单条消息 230 个订阅 | 28.7 KB | 正常,32 ms |
| 单条消息 300 个订阅 | 37.4 KB | **TB 以 1009 关闭连接**(text message too big),一条回推都没有 |
| 单条消息 400 个订阅 | 49.9 KB | 同上 |
| 400 个订阅分 3 片(≤ 24 KB) | 23.9 KB | 正常,400 / 400,43 ms |
| 400 个测点按实体合并成 67 个订阅 | 9.3 KB | 正常,30 ms |

上限来自 TB `server.ws.max_text_message_buffer_size` = 32768(CT110 为缺省值)。超限后适配器会重连并重放同一条大消息,形成**断开 → 重连 → 再断开**的死循环。现有页面只有几十个绑定所以没踩到;接线图一定会踩。

决定:T5.4 同时做**按实体合并订阅**(主要手段,订阅数降到设备数量级)与**分片发送**(兜底,单条 ≤ 24 KB),首发与重连重放两处都覆盖。同事的正式 TbClient 同样需要,结论已可告知。

页面大小:CT110 `/api/**` 请求上限 16 MB;300 节点的图约 100–300 KB,加 10 版历史单次 POST 约 3 MB,在限内。真实大页面的写读留到 T5.9 首次真实发布时验证,不为此往 TB 写测试数据;若届时偏慢,再决定含 `sld` 的页面是否减少历史版数。

## Spike A:X6 画布可行性(2026-09-18,分支 `spike/sld-x6`,不合入主干)

subagent 写验证页,主会话用浏览器实测。结论:**X6 3.x 可以胜任,按下面的做法走。**

| 项 | 结论 |
|---|---|
| API 形态 | 3.x 的插件(Snapline / History / Selection / MiniMap / Dnd / Transform / Keyboard / Clipboard)**全部并入主包** `@antv/x6`,样式由插件自己注入;网上 1.x / 2.x 教程里的 `@antv/x6-plugin-*` 分包写法已不适用 |
| Vue 节点 | `@antv/x6-vue-shape` 的 `register` + Teleport 模式(所有节点组件挂在编辑器这一个 app 下,共享 provide);点击断路器切分合,响应式重绘正常 |
| 母线任意点接线 | **推荐:母线 = 普通 SVG 节点(20 px 透明命中区 + 6 px 粗线)+ 自定义 anchor**,anchor 按连线上存的母线位置取点;拖线到母线上时取垂足并吸附栅格。比较过的备选:母线做成 edge + ratio 锚点(拉伸、框选、对齐线都别扭);母线节点上动态加 port(接点多了 port 管理复杂,且 port 是百分比定位,又回到浮点漂移)——都放弃 |
| 母线拉伸 | 默认「接点保持画面上的绝对位置」→ 与契约把母线接点存成整数距离 `d` 一致 |
| 走线 | X6 自带的 `manhattan` / `orth` 会绕障但**结果不可复现**(运行时没有 X6,画不出同一条线);`manhattan` 还必须把母线排除出障碍。**决定:注册自定义 router `sld`,内部调 model 的 `routeOrthogonal()`**——编辑器与运行时同一个函数,所见即所得;用户手工拖的拐点存 `vertices`,原样使用。connector 用 `rounded`(半径 4) |
| 往返 | 导出 → 清空 → 导入,JSON 深相等(3 间隔与 100 间隔都验过) |
| 性能(301 节点 / 300 线) | 建模型约 500 ms,渲染完成约 600 ms;批量移动 100 个节点 40 ms;拖动时 X6 每步 CPU 约 1 ms。单图 ≤ 300 节点的规模假设成立 |
| **坑:异步渲染** | `async: true` 时清空 / 重载画布后 DOM 里残留旧视图(实测清空后还剩 654 个 edge 视图,画面上是一排残线);`async: false` 无此问题,而同步渲染 300 节点也只要约 600 ms → **T5.5 用 `async: false`** |
| 缺省走线的观感 | 节点被拖离原来的列以后,缺省折线会出 U 形回环,不好看但正确;靠手工拐点修。T5.7 可加「拉直 / 重置走线」 |

## 契约修订(2026-09-18,T5.0 收尾;来自 R2 的疑问、Spike A、YY 提供的现有一次图案例)

案例图:`docs/样例/一次图案例-瓜州收费站微电网.png`(10 kV 双进线 + 两台主变 + 0.4 kV 多面出线柜 + 光伏 / 微网并网柜 / 储能)。

| 修订 | 原因 |
|---|---|
| `SldNode.x / y` = **旋转 / 镜像之后**画面上的包围盒左上角 | 旋转不让节点离开栅格;x6-adapter 按这个语义换算 |
| 栅格 v1 固定 10(`SLD_GRID`) | 图元按 10 画,每张图栅格可变会让端口落不上 |
| 母线接点 `{ bus, t }` → **`{ bus, d }`**,d 为距 (x1,y1) 的整数像素 | 接点恒落栅格、无浮点漂移;与 Spike A「拉伸时保持绝对位置」一致 |
| 图元文字从 `body` 拆到 `texts`;片段里出现 `<text>` 注册时拒绝 | `Wh` 这类字旋转 90° 会躺倒、镜像会反字;`<SldSymbol>` 单独正向画 |
| `labelSlots` 落点按端口同一套规则变换,文字不旋转 | 原先没说清 |
| 没配 `state` 的开关视为常合 | `resolveSwitchState(undefined)` 与 `energize` 统一 |
| 新增 `SldDoc.frames?`:虚线分组框 + 标题 | 案例图里每面柜 / 每个系统都有虚线框(LP3、LP4、微网并网柜、储能系统) |
| 标签加 `color?`('a' / 'b' / 'c' 相色或颜色值) | 案例图的 Uab / Ubc / Uca、Ia / Ib / Ic 按黄 / 绿 / 红区分 |
| 数值标签 `format.map?`:枚举文字 | 案例图的「状态 00 · 0 停止 1 内循环 2 制冷…」这类状态量 |
| 导出 `routeOrthogonal` / `busDirection` / `busOffset` / `symbolPoint` | 给 X6 自定义 router 与 x6-adapter 复用 |

案例图对图元库(T5.2)的补充要求:

- **简化开关**(实心小方块,合位绿色)——0.4 kV 出线回路用它,一页能排下几十条;与国标断路器并存,由画图的人选。
- **横向出线回路**:垂直母线 + 向右的水平馈线 + 末端箭头(现有图的 LP3 / LP4 / LP7 全是这种)→ 图元都要能旋转 90°,`duplicateBay` 要支持纵向排列(dy)。
- **非电气设备框**(除湿机、液冷机、PCS、BATTERY):带名字的矩形,`conduct = 'none'` 或 `'always'`,可点击。
- **状态灯**(「安全检测」绿点):按测点值变色的小圆,走 `state`。
- 进线 / 主变出线柜里的手车、PT、避雷器、接地刀、带电显示器——已在 22 个的清单里。

## 备选与放弃理由

| 备选 | 放弃理由 |
|---|---|
| 外部画图(draw.io / Visio / CAD)导入 SVG 后绑点 | 画图与绑点在两个工具里;改图要重新导出,元素 id 易丢、绑定重做;无电气语义,做不了带电着色与间隔批量复制。只保留「导入图片当底图描摹」 |
| TB 自带 SCADA symbols / FUXA / 乐吾乐 | TB 方案只能 iframe 嵌入,登录态与主题和现有渲染器是两套;FUXA 要另起服务;乐吾乐电力图元有商业授权问题 |
| 图单独存成资产(`ScadaDiagram`),组件按 id 引用 | 多一种资产类型 = 发布、客户可见性、漂移检测、清理都要多做一套;而测点绑定仍得跟着页面走(D2),图单独存只剩几何可复用,不值 |
| 绑定放在图里,组件内部自己调解析器 | 见 D2:按名解析、key 检查、声明 key 校验都要另写遍历 |
| 每节点一条告警绑定 | 见 D3:REST 轮询风暴 |
| 运行时也用 X6 渲染 | 同事宿主要多背一个图编辑库;只读展示用不着 |

## T5.1 验收用例清单

`validateSldDoc`:id 不合字符集 / 重复 id(跨节点、母线、连线、标签)/ 未知图元 / 未知端口 / 悬空线(端点引用不存在)/ 不落栅格(warning)/ 母线非水平垂直 / `conduct = 'switch'` 的节点没有 `state`(warning,视为常合)/ 标签 `attach` 指向不存在的节点 / 无电源点(warning)/ 版本不对。

`energize`:单电源直馈;分位开关后失电;`unknown` 开关后标 `uncertain`;双电源经母联,一侧失电另一侧经母联带电;变压器两侧电压等级不同;母线 `kv` 覆盖继承值;环网不死循环;`conduct = 'none'` 的图元自身带电但不向外传;无电源全失电;连线接在母线中段(t)能导通;孤立元素失电。

`duplicateBay`:节点 / 连线 / 标签整体复制且新 id 唯一;接母线的连线按位移换算 t 并夹取;`pt` 重新编号且绑定同步复制;`rename` 作用到 `node.name`、`node.entity.name`、绑定的 `entity.name`,`entity.id` 置空;选择集内部连线两端都指向新节点;输入不被修改;`count = 0` 原样返回。

`incrementName`:`PDR1_LP1_IED1` 末段 +1;指定段;无数字原样返回;补零宽度保持(`LP01` → `LP02`)。

`migrateSldDoc`:缺省数组补空;未知版本抛错;v1 原样通过。
