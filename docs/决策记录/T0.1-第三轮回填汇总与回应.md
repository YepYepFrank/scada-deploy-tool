## 2. 契约变化(§4.3b 修订)

第二轮冻结的 `params = { stationId?, deviceId?, keys?, metric? }` 是按「kz 会提供站点级通用接口」猜的;接口文档表明通用接口是**按实体查 tskv 归档表**,与 TB 自己的 `values/timeseries` 同形,只是路径多了粒度段。改为两种明确形状,tbClient 按 `keys` 是否为数组分派:

```ts
// 通用历史(任意实体 + 任意 key;≥ 3 天窗口或按天 / 月 / 年统计)
{ entity: EntityRef; keys: string[]; agg?: 'AVG' | 'MAX' | 'MIN' | 'ZD'; startTs?: number; endTs?: number }
// 业务统计(一期只有收益趋势)
{ stationId: string; metric?: 'inc' | 'cost' | 'net' }
```

- `window`(缺省 `30d`)→ `endTs = now`、`startTs = now - window`;显式 `startTs / endTs` 优先(报表按自然月查时用)。
- `interval` 缺省按窗口选:≤2h 1m;≤24h 5m;≤7d 1h;≤90d 1d;更长 1M。
- `series` = `data` 里「量名 → 升序 `[{ ts, value }]`」,`createTime / zdValue` 忽略;`meta = { bucket, agg, startTs, endTs }`。
- 这是 `params: Record<string, unknown>` 内部的约定,JSON Schema 不变,已发布页面不受影响。
