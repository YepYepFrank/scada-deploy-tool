## 一、东西存在哪里(三层「保存」)

| 内容 | 存放位置 | 说明 |
|---|---|---|
| **站点规则**(认领的设备与测点、运算、告警、输出前缀) | TB 站点资产(type `tbsite`)的服务端属性 `siteConfig`(+ `siteConfigHistory` 10 版) | 权威副本,发布即持久化;文件形态 `sites/<站点>.tbsite.json`,可用 CLI 重放 |
| **页面组态**(一页一个 JSON) | TB `ScadaPage` 资产的服务端属性 `pageConfig`(+ `pageConfigHistory` 10 版、`additionalInfo.version`) | 站点资产 `Contains` 它,并分给站点所属 Customer;文件形态 `sites/pages/<站点>-<页面>.pageconfig.json` |
| 项目文件 `.scadaproj` | 向导第 5 步下载 | 规则 + 页面(实体按名)+ 连接信息(不含密码),换 TB 实例可重放 |
| 本机草稿 / 记住账号 | 使用者浏览器 localStorage | 个人工作现场,不用于交付;只存账号名,不存密码 |
| **前端页面本体** | `dev/apps/deploy-tool` 源码;`pnpm build` → `dist/`;`pnpm build:site` → `dist-site/site.html` | 配置驱动:改配置重新发布即可,前端不用重新打包 |

## 二、交付物清单

1. `dist/`:`provisioner.html`(向导)、`editor.html`(独立组态编辑器)、`site.html`(大屏)+ `assets/`。
2. `dist-site/site.html`:单文件大屏(约 1.9 MB,JS / CSS / 字体全内联;0.5.0 起大屏用了字体包所以变大),放任意静态目录即可用。
   旁边还有一个 `company-logo-*.png`(浏览器标签页图标),一起拷;只拷 html 也能用,只是标签页图标 404。
3. 包的 tarball(`pnpm pack:delivery`),给宿主应用 `import`:`@grid/scada-renderer` + `@grid/tb-client` 两个是必需的;
   `@grid/tbsite-compiler` 只有用命令行发布器时才需要。给庄的交付一般 `--only renderer,tb-client`。
4. `sites/`:各站点的 `*.tbsite.json` 与 `pages/*.pageconfig.json`(存档 + 重放)。
5. 本指南 + `操作说明-工程人员.md`。

```bash
cd dev
pnpm install
pnpm -F deploy-tool build     # dist/
pnpm -F deploy-tool build:site
pnpm pack:delivery            # 构建三个包 + 打 tarball 到 delivery/,附交付清单
pnpm pack:delivery --only renderer,tb-client --out delivery/<目录>   # 只打两个、放到指定目录;--no-build 跳过构建
```

`delivery/` 不进 git;`交付清单.md` 每次打包都会覆盖,只反映最后一次。

**给同事(庄)的交付包**是手工组装的一个文件夹 + 同名 zip,放在 `delivery/给庄-<主题>-<日期>/`:两个 tgz、`交付清单.md`、
`00-先看这份-<本版>交付说明.md`(取自 `docs/给同事的-渲染器<版本>交付-<日期>.md`)、更早几版的交付说明(她要改的那份标在文件名里)、
`渲染器 CHANGELOG.md`,以及她需要的方案 / 约定说明。新包出来后旧包删掉,免得转错。

### 交付包一定要能追溯到提交

**同一个版本号可能对应不止一份代码**(早期 `@grid/scada-renderer` 停在 0.2.0 好几周;现在每次交付都升版本,2026-10-10 为 0.13.0),
所以 `pack:delivery` 照样给每个包打上提交号,两处都有:

- **文件名**:`grid-scada-renderer-0.13.0-9923ef0.tgz`;
- **包内 `build-info.json`**:完整提交号、提交主题、提交时间、分支、打包时间。文件名被改、
  被转手几次之后仍然查得到。

拿到包的人核对:

```bash
cat node_modules/@grid/scada-renderer/build-info.json   # commit 就是源码位置
git -C <仓库> show <commit>                              # 先 git fetch
```

宿主应用可以 `import info from '@grid/scada-renderer/build-info.json'` 把提交号显示在界面角落,
现场出问题时截图就能确认跑的是哪一版(纯 Node ESM 里要加 `with { type: 'json' }`)。

`pack:delivery` 会**拒绝**两种打不出可追溯包的情况:工作区有未提交改动(提交号对不上代码),
或 HEAD 还没推到 `origin/main`(提交号在共享仓库里查不到)。自己临时验证可以
`--allow-dirty` / `--allow-unpushed`,前者会把文件名标成 `+dirty`。

## 三、部署方式

### 方式 A(推荐):与 ThingsBoard 同机 / 同域,nginx 单端口反代

前端、TB REST / WebSocket、kz 三者同源,浏览器没有跨域问题,kz 也不暴露到外网。

```nginx
# http{} 级:WebSocket 的 Connection 头按是否 upgrade 决定(放 conf.d 或 nginx.conf 的 http 块里)
map $http_upgrade $connection_upgrade { default upgrade; '' close; }

server {
  listen 80;
  server_name gridops.example.internal;
  root /var/www/gridops;            # dist/ 的内容放这里
  index provisioner.html;

  # ThingsBoard REST + WebSocket(遥测订阅走 /api/ws,必须带 upgrade 头)
  location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;       # WS 长连接
  }

  # kz 扩展服务:前端以 /kz 为前缀,后面接 kz 自己的 /kzserver/...(去掉 /kz 再转)
  # 反代层先拿请求头里的 TB token 去 TB 验一次(auth_request):没有 / 无效 token 直接 401,不进 kz。
  # 现场 kz 必须是 2026-09-08 之后的包(tskv/** 校验 token);kz 仍不按实体归属过滤,8099 不要直接暴露,只走这段反代
  location /kz/ {
    auth_request /_tb_auth;
    rewrite ^/kz(/.*)$ $1 break;
    proxy_pass http://127.0.0.1:8099;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
  }
  location = /_tb_auth {
    internal;
    proxy_pass http://127.0.0.1:8080/api/auth/user;
    proxy_pass_request_body off;
    proxy_set_header Content-Length "";
    proxy_set_header X-Authorization $http_x_authorization;
  }
}
```

访问:向导 `http://主机/provisioner.html`(第 1 步「＋新项目」录 TB 地址,同域可留空),大屏 `http://主机/site.html?site=<站点名>`(同域不用 `base`,kz 自动走 `/kz`)。

大屏地址参数:`site=<站点名>`(必填)、`page=<页面资产 id>`(直接打开某一页)、`cards`(直接进卡片库检视)、
`base=<TB 地址>`(不同域时)、`kz=<kz 地址>`;旧书签里的 `env=mirror` 仍认。

> **请求体大小**(未实测,建议加):页面发布是一次 POST 同时写 `pageConfig` 和最多 10 版 `pageConfigHistory`;带大接线图(压测页约 108 KB)
> 和抬头 logo(data URI,上限约 200 KB)的页面攒满 10 版历史后可能超过 nginx 默认的 1 MB,返回 413。方式 A 的 `location /api/` 里建议加
> `client_max_body_size 8m;`。09-08 的演练早于接线图功能,没覆盖到。

### 方式 A 演练记录(2026-09-08,镜像 CT 111 端口 8088)

上面这份配置原样在 TB 镜像容器里跑过一遍(`nginx 1.22`,`/etc/nginx/sites-available/gridops`,静态目录 `/var/www/gridops`,记录 `联调记录/nginx-同域部署演练-2026-09-08.md`):静态页 200;`/api/auth/login` 经反代登录成功;`/api/ws` 经反代完成 WebSocket 升级并收到遥测推送;`/kz/` 无 token → 401(nginx 拦下,不到 kz),带客户 token → kz 数据;客户账号打开 `site.html?site=xrs-mirror-test`(不带 `base` / `kz`)「运营总览」9 个组件全部有数。

### 方式 B:单文件大屏放任意静态目录(含同事平台的 iframe)

把 `dist-site/site.html` 丢进任意静态目录,URL 带上 TB 地址:

```
http://他们的域名/任意路径/site.html?site=<站点名>&base=http://TB主机:8080&kz=http://TB主机:8099
```

- 打开先登录(TB 账号,token 只存本标签页的 sessionStorage);登录身份能看到哪些页面由 TB 里的 Customer 分配决定,**没有匿名 / Public 路径**。
- `base=` 直连时浏览器会对 TB 发跨域请求:TB CE 默认放行 `/api` 跨域(含 WS,已在镜像实测);如现场 TB 前面有反代,反代要放行 CORS 或改用方式 A。
- 用了 `base=` 又不给 `kz=` 时,**所有走 kz 的绑定**(`ext`,长曲线和收益趋势)都显示「kz 未配置」,其它组件不受影响(同域部署不用给,自动走 `/kz`)。
- iframe 集成:`<iframe src="上面的 URL" style="width:100%;height:100%;border:0"></iframe>`;同一个文件配不同 `site` 就是不同站点。

### 方式 C:宿主应用直接 import 渲染器(同事的 Vue 应用,T2.6)

```bash
pnpm add ./grid-scada-renderer-0.13.0-<提交号>.tgz ./grid-tb-client-0.0.3-<提交号>.tgz   # 或私有 registry
# 渲染器的 peer 依赖锁定 @grid/tb-client 的确切版本,两个包要同一次交付里的
```

```ts
// main.ts
import '@grid/scada-renderer/style.css'

```

```vue
<!-- 路由 /scada/:assetId -->
<script setup>
import { ScadaPage, provideDataSource, validatePageConfig } from '@grid/scada-renderer'
provideDataSource(tbClient) // 同事的 TbClient;就位前可用 @grid/tb-client 的 LegacyDataSource
const raw = await tb.getAttributes('ASSET', assetId, 'SERVER_SCOPE', ['pageConfig'])
const checked = validatePageConfig(JSON.parse(raw.pageConfig))
</script>
<template>
  <div style="height: calc(100vh - 56px)"><ScadaPage v-if="checked.ok" :config="checked.value" /></div>
</template>
```

```ts
// vite.config.ts —— 必需,否则 ECharts 被预构建成两份、图表空白
optimizeDeps: { include: ['echarts/core', 'echarts/charts', 'echarts/components', 'echarts/renderers'] }
```

页面列表 = 站点资产 `Contains` 关系里 type 为 `ScadaPage` 的资产(`additionalInfo.kind = 'cards'` 的是卡片库,不当大屏页列)。
宿主自带 `vue`;`echarts` 是渲染器的依赖,构建时外置,上面的 `optimizeDeps` 仍然必需。宿主构建产物里只应有一份 Vue。
细节见 `packages/renderer/README.md`「接入示例」、`给同事的开发说明.md` §3 与各版 `给同事的-渲染器*交付-*.md`。

**宿主要知道的几件事(0.9.0 以后)**:

- **tbClient 的 `getHistory` 要收绝对区间**:第三个参数是 `TimeRange = '24h' 这类字面量 | { from, to }`,`ExtQuery.range` 同理,
  用 `@grid/tb-client` 的 `resolveTimeRange` 一行换算。不改的话,用到绝对区间的曲线报「数据不可用」。
  **顺序:宿主先升到 0.9.0 以上,工具才能发布带「跟随页面上下文」绑定的页面**,0.8.0 及更早的渲染器会把这类页面判为无效。
- **绑定上下文**:`<ScadaPage>` / `<ScadaWidget>` 的 `:binding-context`,或 `provideBindingContext(ctx)`;键 `selectedSite / selectedDevice /
  selectedMeasurePoint / timeRange / custom.*`。组件发 `widget-event`(整卡 `click`、表格 `row-click`、告警 `alarm-click`、接线图 `node-click`)。
- **其它新东西**:一次接线图组件 `sld`(0.4.0 起;0.11.0 起开关红合绿分,0.12.0 起数值数码框,0.13.0 起 10 kV 紫)、按卡片引用的 `<ScadaWidget>` /
  `pickWidget` 与卡片库模板 `cards`、组件放大 `expandable`、背景层 `decor`、可选字体包 `import '@grid/scada-renderer/fonts.css'`(约 665 KB)、
  页面抬头 `PageConfig.header`(`:header="false"` 关掉)。完整清单见渲染器 `CHANGELOG.md`。
- **WebSocket 单条消息上限 32 KB**:一张接线图 300–400 个测点,TbClient 合并订阅时要分片(24000 字节一片),否则 TB 以 1009 断开。
  见 `给同事的-WS订阅单条消息上限-2026-09-18.md`。

### 命令行发布(脚本化 / CI)

```bash
pnpm -F @grid/tbsite-compiler build          # 先构建:tbsite.mjs 只是个壳,跑的是 dist(没构建退出码 2;改了编译器也要重新构建)
node packages/compiler/bin/tbsite.mjs validate sites/<站点>.tbsite.json
node packages/compiler/bin/tbsite.mjs plan     sites/<站点>.tbsite.json          # 只打印写入计划,不连 TB
node packages/compiler/bin/tbsite.mjs drift    sites/<站点>.tbsite.json          # 本地声明 vs 线上(只读;--strict 有差异退出码 1,给 CI 用)
node packages/compiler/bin/tbsite.mjs publish  sites/<站点>.tbsite.json --by <人>     # 规则:CF / 规则链 / 资产
node packages/compiler/bin/tbsite.mjs page     sites/pages/<文件> --site <站点> --name "<页面名>" --by <人>
node packages/compiler/bin/tbsite.mjs pages    --site <站点> [--widgets]
```

还有 `cleanup`、`migrate`(ADR-003 迁移表)、`alarm-export`(告警导出成同事格式),用法见 `tbsite` 不带参数的输出。

凭据只从环境变量 / 向上找到的 `.env.local` 读(`TB_BASE / TB_USER / TB_PASSWORD`),不接受 `--password` 明文;
可用 `--base` / `--user` / `--password-env <变量名>` / `--env-file <文件>` 换。**不给 `TB_BASE` 时默认连镜像 `http://192.168.20.61:8080`**。

> **注意**:线上站点资产的 `siteConfig` 可能比仓库里的 `sites/*.tbsite.json` 新(现场在向导里改过、测点标签填了中文)。
> 拿文件发布前先 `drift` 看一眼,有差异就以线上为准(把线上 `siteConfig` 存成文件再发),别用旧文件把现场改动覆盖掉。

**切换后端**:`dev/.env.local` 的 `TB_BASE`(与可选的 `KZ_BASE`,不填默认同主机 `:8099`)只影响开发服务(5173)/ `pnpm -F deploy-tool preview`(4173)的代理、
命令行和 live 用例。**构建产物不绑定后端**:生产走同域 `/api`,或大屏地址带 `base=`。

## 四、权限模型(部署前要理顺)

- 页面资产、汇聚资产随站点资产分给**同一个 Customer**;客户账号(CUSTOMER_USER)登录大屏只看到分给它的页面,页面里绑定了未分配实体的组件显示「不可用」并在顶栏汇总。
- **已知缺口(联调环境待办 ⑦,2026-09-10)**:TB 对**未分配设备的「历史区间」查询照样回 200 和真实数据**(实时订阅、最新值、属性才 403)。
  所以**查清之前不要对外说「客户只能看到分给它的数据」**;一个项目一个客户时影响不大,改成一站一客户之前必须先查清。
- **一个资产只能属于一个 Customer**。同事现有大屏的资产(`SITE_OVERVIEW / REALTIME_*`)与我们的站点 / 设备如果分属不同 Customer,同一张页面没有任何客户账号能看全——上线前必须统一到一个项目客户(联调环境待办 ⑥;2026-09-07 晚三方已同意统一,镜像上已并到站点客户「仙人山服务区」并复验)。
- 租户账号看全部;向导必须用租户账号(要写规则链 / 资产)。

## 六、给运维的最小操作卡

```text
1. 解压 dist/ 到 nginx 站点目录,按方式 A 配 /api(必配)与 /kz(可选)两段反代
2. 打开 provisioner.html → 第 1 步填 TB 地址与租户账号 → 五步走完点发布(详见 操作说明-工程人员.md)
   注意:第 3 步点保存就会写 TB(结果资产、站点资产、Contains 关系),进第 3 步时还会和平台同步、列出冲突;
   规则链、计算字段、页面要到第 5 步发布才写。告警链会在 Root 上加一个本站点自己的转发节点(Root 归高潮维护,工具只动这一个节点)
3. 大屏入口:site.html?site=<站点名>;客户账号登录即见分配给它的页面
4. 以后改配置在向导里改、再发布,前端文件不用动;存档用第 5 步下载的 .scadaproj / sites/ 目录
5. 发布出问题:第 5 步「发布历史」可回滚上一版;失败项点「重试失败项」(所有写入幂等)
```
