# GRID·OPS 前端交付部署指南 v2(2026-09-07)

> 目标读者:接手部署的同事与现场运维。v1(`../../docs/前端交付部署指南.md`,2026-09 初)针对 `tb-frontend/` 单页应用;v2 起前端在 `dev/apps/deploy-tool`,页面渲染由 `@grid/scada-renderer` 包提供,宿主应用可以直接 `import`。后端只依赖 ThingsBoard CE 4.3.x 的 REST / WebSocket,可选 kz 扩展服务(归档查询);没有独立服务端。

## 一、东西存在哪里(三层「保存」)

| 内容 | 存放位置 | 说明 |
|---|---|---|
| **站点规则**(认领的设备与测点、运算、告警、输出前缀) | TB 站点资产(type `tbsite`)的服务端属性 `siteConfig`(+ `siteConfigHistory` 10 版) | 权威副本,发布即持久化;文件形态 `sites/<站点>.tbsite.json`,可用 CLI 重放 |
| **页面组态**(一页一个 JSON) | TB `ScadaPage` 资产的服务端属性 `pageConfig`(+ `pageConfigHistory` 10 版、`additionalInfo.version`) | 站点资产 `Contains` 它,并分给站点所属 Customer;文件形态 `sites/pages/<站点>-<页面>.pageconfig.json` |
| 项目文件 `.scadaproj` | 向导第 5 步下载 | 规则 + 页面(实体按名)+ 连接信息(不含密码),换 TB 实例可重放 |
| 本机草稿 / 记住账号 | 使用者浏览器 localStorage | 个人工作现场,不用于交付;只存账号名,不存密码 |
| **前端页面本体** | `dev/apps/deploy-tool` 源码;`pnpm build` → `dist/`;`pnpm build:site` → `dist-site/site.html` | 配置驱动:改配置重新发布即可,前端不用重新打包 |

## 二、交付物清单

1. `dist/`:`provisioner.html`(向导)、`editor.html`(独立组态编辑器)、`site.html`(大屏)+ `assets/`。
2. `dist-site/site.html`:单文件大屏(约 0.8 MB,JS / CSS 全内联),放任意静态目录即可用。
3. `packages/renderer` 与 `packages/tb-client` 的 tarball(`pnpm -F <包> pack`),给宿主应用 `import`。
4. `packages/compiler/dist` + `bin/tbsite.mjs`:命令行发布器(脚本化 / CI 用,可选)。
5. `sites/`:各站点的 `*.tbsite.json` 与 `pages/*.pageconfig.json`(存档 + 重放)。
6. 本指南 + `操作说明-工程人员.md`。

```bash
cd dev
pnpm install
pnpm -r build                 # 三个包
pnpm -F deploy-tool build     # dist/
pnpm -F deploy-tool build:site
```

## 三、部署方式

### 方式 A(推荐):与 ThingsBoard 同机 / 同域,nginx 单端口反代

前端、TB REST / WebSocket、kz 三者同源,浏览器没有跨域问题,kz 也不暴露到外网。

```nginx
# http{} 级:WebSocket 的 Connection 头按是否 upgrade 决定(放 conf.d 或 nginx.conf 的 http 块里)
map $http_upgrade $connection_upgrade { default upgrade; '' close; }

server {
  listen 80;
  server_name gridops.example.internal;
  root /var/www/gridops;            # dist/ 的内容放这里
  index provisioner.html;

  # ThingsBoard REST + WebSocket(遥测订阅走 /api/ws,必须带 upgrade 头)
  location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;       # WS 长连接
  }

  # kz 扩展服务:前端以 /kz 为前缀,后面接 kz 自己的 /kzserver/...(去掉 /kz 再转)
  # 反代层先拿请求头里的 TB token 去 TB 验一次(auth_request):没有 / 无效 token 直接 401,不进 kz。
  # 现场 kz 必须是 2026-09-08 之后的包(tskv/** 校验 token);kz 仍不按实体归属过滤,8099 不要直接暴露,只走这段反代
  location /kz/ {
    auth_request /_tb_auth;
    rewrite ^/kz(/.*)$ $1 break;
    proxy_pass http://127.0.0.1:8099;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
  }
  location = /_tb_auth {
    internal;
    proxy_pass http://127.0.0.1:8080/api/auth/user;
    proxy_pass_request_body off;
    proxy_set_header Content-Length "";
    proxy_set_header X-Authorization $http_x_authorization;
  }
}
```

访问:向导 `http://主机/provisioner.html`(第 1 步「＋新项目」录 TB 地址,同域可留空),大屏 `http://主机/site.html?site=<站点名>`(同域不用 `base`,kz 自动走 `/kz`)。

### 方式 A 演练记录(2026-09-08,镜像 CT 111 端口 8088)

上面这份配置原样在 TB 镜像容器里跑过一遍(`nginx 1.22`,`/etc/nginx/sites-available/gridops`,静态目录 `/var/www/gridops`,记录 `联调记录/nginx-同域部署演练-2026-09-08.md`):静态页 200;`/api/auth/login` 经反代登录成功;`/api/ws` 经反代完成 WebSocket 升级并收到遥测推送;`/kz/` 无 token → 401(nginx 拦下,不到 kz),带客户 token → kz 数据;客户账号打开 `site.html?site=xrs-mirror-test`(不带 `base` / `kz`)「运营总览」9 个组件全部有数。

### 方式 B:单文件大屏放任意静态目录(含同事平台的 iframe)

把 `dist-site/site.html` 丢进任意静态目录,URL 带上 TB 地址:

```
http://他们的域名/任意路径/site.html?site=<站点名>&base=http://TB主机:8080&kz=http://TB主机:8099
```

- 打开先登录(TB 账号,token 只存本标签页的 sessionStorage);登录身份能看到哪些页面由 TB 里的 Customer 分配决定,**没有匿名 / Public 路径**。
- `base=` 直连时浏览器会对 TB 发跨域请求:TB CE 默认放行 `/api` 跨域(含 WS,已在镜像实测);如现场 TB 前面有反代,反代要放行 CORS 或改用方式 A。
- `kz=` 不给则 30 天以上的曲线(`ext` 绑定)显示「kz 未配置」,其它组件不受影响。
- iframe 集成:`<iframe src="上面的 URL" style="width:100%;height:100%;border:0"></iframe>`;同一个文件配不同 `site` 就是不同站点。

### 方式 C:宿主应用直接 import 渲染器(同事的 Vue 应用,T2.6)

```bash
pnpm add ./grid-scada-renderer-0.2.0.tgz ./grid-tb-client-0.0.1.tgz   # 或私有 registry
```

```ts
// main.ts
import '@grid/scada-renderer/style.css'
import { registerBuiltins } from '@grid/scada-renderer'
registerBuiltins()
```

```vue
<!-- 路由 /scada/:assetId -->
<script setup>
import { ScadaPage, provideDataSource, validatePageConfig } from '@grid/scada-renderer'
provideDataSource(tbClient) // 同事的 TbClient;就位前可用 @grid/tb-client 的 LegacyDataSource
const raw = await tb.getAttributes('ASSET', assetId, 'SERVER_SCOPE', ['pageConfig'])
const checked = validatePageConfig(JSON.parse(raw.pageConfig))
</script>
<template>
  <div style="height: calc(100vh - 56px)"><ScadaPage v-if="checked.ok" :config="checked.value" /></div>
</template>
```

```ts
// vite.config.ts —— 必需,否则 ECharts 被预构建成两份、图表空白
optimizeDeps: { include: ['echarts/core', 'echarts/charts', 'echarts/components', 'echarts/renderers'] }
```

页面列表 = 站点资产 `Contains` 关系里 type 为 `ScadaPage` 的资产。宿主自带 `vue`、`echarts`;宿主构建产物里只应有一份 Vue。细节见 `packages/renderer/README.md`「接入示例」与 `给同事的开发说明.md` §3。

### 命令行发布(脚本化 / CI)

```bash
node packages/compiler/bin/tbsite.mjs validate sites/<站点>.tbsite.json
node packages/compiler/bin/tbsite.mjs publish  sites/<站点>.tbsite.json --by <人>     # 规则:CF / 规则链 / 资产
node packages/compiler/bin/tbsite.mjs page     sites/pages/<文件> --site <站点> --name "<页面名>" --by <人>
node packages/compiler/bin/tbsite.mjs pages    --site <站点>
```

凭据只从环境变量 / 向上找到的 `.env.local` 读(`TB_BASE / TB_USER / TB_PASSWORD`),不接受 `--password` 明文。

## 四、权限模型(部署前要理顺)

- 页面资产、汇聚资产随站点资产分给**同一个 Customer**;客户账号(CUSTOMER_USER)登录大屏只看到分给它的页面,页面里绑定了未分配实体的组件显示「不可用」并在顶栏汇总。
- **一个资产只能属于一个 Customer**。同事现有大屏的资产(`SITE_OVERVIEW / REALTIME_*`)与我们的站点 / 设备如果分属不同 Customer,同一张页面没有任何客户账号能看全——上线前必须统一到一个项目客户(联调环境待办 ⑥;2026-09-07 晚三方已同意统一,镜像上已并到站点客户「仙人山服务区」并复验)。
- 租户账号看全部;向导必须用租户账号(要写规则链 / 资产)。

## 五、交付前必须处理的安全项

| 项 | 状态 / 动作 |
|---|---|
| 内嵌凭据 | 已清除(T3.8):没有任何内置账号、无 Public 匿名读;开发期预填只来自 `.env.local`,构建产物不含 |
| 向导「记住账号」 | 2026-09-08 起只存账号名(明文 JSON,30 天),不存密码;旧版存过的账号 + 密码条目在下次打开向导时自动改写为只含账号 |
| kz 鉴权 | **token 校验已修**(2026-09-08 新包 md5 `fb8e502a…`,`pnpm -F @grid/tb-client test:live` 的 `kz-auth` 组通过即为正确版本;旧包 `b0a7b5f9…` 不校验 `tskv/**`,不得上线)。**仍未按实体归属过滤**:任何能登录的客户账号可读全库归档(联调环境待办 ⑤b)。现场:8099 不对外,只走方式 A 的同机反代;客户可达的网络不要开 8099 |
| TB 跨域 | 方式 B 依赖 TB 放行 `/api` 跨域;生产 TB 前有反代时按需放行或改方式 A |
| 遥测保留 | 生产 TB 无 TTL,kz 定时任务 3–7 天清秒级数据;页面短历史只取 3 天内,更长走 kz |

## 六、给运维的最小操作卡

```text
1. 解压 dist/ 到 nginx 站点目录,按方式 A 配 /api(必配)与 /kz(可选)两段反代
2. 打开 provisioner.html → 第 1 步填 TB 地址与租户账号 → 五步走完点发布(详见 操作说明-工程人员.md)
3. 大屏入口:site.html?site=<站点名>;客户账号登录即见分配给它的页面
4. 以后改配置只重复第 2 步,前端文件不用动;存档用第 5 步下载的 .scadaproj / sites/ 目录
5. 发布出问题:第 5 步「发布历史」可回滚上一版;失败项点「重试失败项」(所有写入幂等)
```
