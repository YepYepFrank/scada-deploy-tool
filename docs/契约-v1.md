## 1. PageConfig

一页 = 一个模板 + 若干放在槽位里的组件。标头 / 菜单 / 时钟**不在**契约内,归宿主应用或独立薄壳。

```ts
interface PageConfig {
  schemaVersion: 1
  template: string          // 模板 id,注册表中查;^[a-z][a-z0-9-]*$
  theme?: string
  title?: string            // 供宿主标头显示;渲染器不画
  widgets: WidgetConfig[]
}
interface WidgetConfig {
  id: string                // 页内唯一;工具生成 w-<slot>;^[A-Za-z0-9_-]+$
  slot: string              // 模板槽位名
  type: string              // 组件类型,注册表中查
  props?: Record<string, unknown>            // 由组件 propsSchema 约束
  bindings: Record<string, Binding | Binding[]>  // 绑定槽位名 → 数据来源
  actions?: Record<string, Action>           // 契约保留,一期不实现
}
```

| 字段 | 规则 | 说明 |
|---|---|---|
| `schemaVersion` | 常量 `1` | 渲染器遇到其他值渲染错误态,不猜 |
| `template` / `type` | 小写 kebab-case | 与注册表 id 一致 |
| `id` | 页内唯一 | 撤销 / 重做与 diff 靠它;编辑器不让用户改 |
| `props` | 可选 | 缺省用组件 `defaults`;未知属性由渲染器按 propsSchema 拒绝 |
| `bindings` | 必填(可为空对象) | 声明了 `multiple: true` 的绑定槽位**必须**是数组(单条也写一项的数组);非 multiple 槽位必须是单个对象。JSON Schema 不区分,注册表运行时强制(B2,庄艳芹:统一数组) |
| `actions` | 可选 | 一期渲染器只校验形状并把组件画成禁用态;不下发任何指令(B5) |

其他字段一律拒绝(`additionalProperties: false`),防止工具与渲染器各自「悄悄加字段」。

## 2. Binding(六种取数方式)

```ts
type Binding =
  | { mode: 'ts';         entity: EntityRef; key: string }
  | { mode: 'ts-history'; entity: EntityRef; keys: string[]; window: string; agg?: Aggregation }
  | { mode: 'attr';       entity: EntityRef; scope: 'SERVER_SCOPE'|'SHARED_SCOPE'|'CLIENT_SCOPE'; key: string }
  | { mode: 'alarm';      entity: EntityRef; types?: string[] }
  | { mode: 'const';      value: unknown }
  | { mode: 'ext';        source: string; window?: string; interval?: ExtInterval; params: Record<string, unknown> }  // kz 归档(A4)
type EntityRef   = { type: 'DEVICE' | 'ASSET'; id: string; name?: string }   // name 仅供显示,发布时写入(A2)
type Aggregation = 'AVG' | 'MIN' | 'MAX' | 'SUM' | 'COUNT' | 'NONE'
```

| mode | 渲染器行为 | 典型组件 | 备注 |
|---|---|---|---|
| `ts` | `subscribeTs`,首次给最新值 | 数字卡、仪表、指示灯 | |
| `ts-history` | `getHistory` 后 `subscribeTs` 追加 | 曲线、表格 | `window` 格式 `^\d+(m|h|d)$`,如 `15m` / `24h` / `7d`(B1);`agg` 缺省由数据层按窗口自适应 |
| `attr` | `subscribeAttr` | 指示灯、文本 | |
| `alarm` | `subscribeAlarms(entity, types)` | 告警列表、状态卡、横幅 | `types` 不填为全部(B4) |
| `const` | 直接注入 | 图片地址、文本、编辑器缩略图假数据 | |
| `ext` | `DataSource.ext(query)`,结果按 `series` 归一 | 逐日 / 逐月曲线、收益表、任何 ≥ 3 天窗口或 ≥ 1 天粒度的统计 | **TB 只保留 3–7 天原始遥测**(生产 TB 无 TTL,kz 定时任务 3–7 天清秒级数据;第三轮回填),长期数据在 kz;`interval` ∈ `1m/5m/1h/1d/1M/1y`;`params` 形状见 §4.3b |

**路由约定(工具侧)**:绑定选择器按窗口自动选取——窗口 ≤ 3 天且粒度 < 1 天走 `ts-history`;否则走 `ext`。`ts-history` 的语义收窄为「TB 保留期内的短窗口」。

## 3. Action(契约保留,二期实现)

```ts
type Action =
  | { kind: 'rpc';  entity: { type: 'DEVICE'; id: string }; method: string; confirm?: boolean }
  | { kind: 'attr'; entity: { type: 'DEVICE'; id: string }; scope: 'SHARED_SCOPE'|'SERVER_SCOPE'; key: string }
```

## 4. DataSource(渲染器需要的数据能力;tbClient 实现)

```ts
interface DataSource {
  readonly status: 'connecting' | 'live' | 'offline'
  onStatus(cb: (s: ConnectionStatus) => void): Unsubscribe
  subscribeTs(entity, keys, cb: (u: TsUpdate[]) => void, onError?: (e: Error) => void): Unsubscribe
  subscribeAttr(entity, scope, keys, cb: (u: AttrUpdate[]) => void, onError?: (e: Error) => void): Unsubscribe
  subscribeAlarms(entity, types | undefined, cb: (a: AlarmInfo[]) => void, onError?: (e: Error) => void): Unsubscribe
  getHistory(entity, keys, window, agg?): Promise<Record<string, TsPoint[]>>
  getLatest(entity, keys): Promise<Record<string, TsPoint | null>>
  ext?(query: ExtQuery): Promise<ExtResult>          // kz 归档;草案期可选,冻结时改必选
}
type ExtQuery  = { source: string; window?: string; interval?: ExtInterval; params: Record<string, unknown> }
type ExtResult = { series: Record<string, TsPoint[]>; meta?: Record<string, unknown> }
type TsPoint  = { ts: number; value: number | string | boolean | null }
type TsUpdate = { key: string; points: TsPoint[] }
```

`onError`(2026-09-06,T3.6 补充,可选参数,向后兼容):订阅被 TB 拒绝时回调**一次**,典型是 CUSTOMER_USER 订阅未分配给它的实体——WS 回 `errorCode≠0`「Failed to fetch data!」、告警轮询 REST 403。渲染器据此把对应组件置为错误态并汇总「N 个绑定在该 Customer 下不可见」,否则只能一直空着。没有这条通道的实现可以不接;但 T3.10 要求同事版对无权实体给明确错误而非静默无数据,建议接上。

### 4.1 与开发计划 §5.3 草案的差别

草案写的是 `status: Readonly<Ref<…>>`。这里改为「当前值 + `onStatus` 回调」,理由:`DataSource` 位于 tbClient 核心,不应依赖 Vue;Vue 适配层(`@grid/tb-client/vue`)再把它包成 `ref`。对同事的实现没有额外负担(C3)。

### 4.2 对实现方(tbClient)的要求(对应 T0.1 清单 C1–C6)

| # | 要求 | 契约里的体现 |
|---|---|---|
| C1 | 所有订阅返回取消函数 | `Unsubscribe` |
| C2 | 历史按窗口自适应聚合:≤2h 原始;2h–24h AVG/5min;24h–7d AVG/1h;>7d AVG/1d | `getHistory` 注释;渲染器不传 `agg` 时由数据层决定 |
| C3 | 连接状态可观察 | `status` + `onStatus` |
| C4 | 值归一化为 number / boolean;不存在的 key 为 `null` | `TsPoint.value`、`getLatest` 返回 `null` |
| C5 | `login()` / `setToken()` 都支持 | 不在 DataSource 内,属 `TbClient` 构造与方法(T1.1) |
| C6 | 错误分三类 | 不在 DataSource 内,属 `TbClientError.kind`(T1.1) |

**不要求**:一条 WS、引用计数去重、零依赖(架构 §0 ③④)。

**实现语言**(T0.1 回填 C8):tb-client 包**允许用 JS 编写**;`.d.ts` 由 YY 按本接口手写并随包发布,类型仍是权威。`request.js` / `websocket.js` 移入包内、宿主改 import 路径(回填「直接 import」的等价做法),不复制两份。

### 4.3 回调语义

- `subscribeTs`:首次回调必须包含当前最新值(实现上等价于先 `getLatest` 再订阅,或 TB WS 首包);之后每次推送增量。
- `subscribeAlarms`:每次回调给出该实体**当前活动告警全集**,渲染器整体替换,不做增量合并。
- 所有回调在数据层线程 / 微任务中触发,渲染器负责把值放进响应式状态;回调内抛错不得中断连接。

### 4.3b `ext`(kz)的 params 与结果分工(2026-09-06,第三轮回填定稿)

```ts
// ExtQuery.params(source = 'kz'),按 keys 是否为数组分派两种查询:
// ① 通用历史(任意实体 + 任意 key;≥ 3 天窗口或按天 / 月 / 年统计)
{ entity: EntityRef; keys: string[]; agg?: 'AVG' | 'MAX' | 'MIN' | 'ZD'; startTs?: number; endTs?: number }
//    → GET {kz}/kzserver/tskv/{桶}/telemetry/{type}/{id}/values/timeseries?keys&startTs&endTs&interval&agg
//    window(缺省 30d)→ endTs = now、startTs = now - window;显式 startTs / endTs 优先
//    interval → 路径段 + 毫秒:1m→minute/60000 · 5m→minutefive/300000 · 1h→hour/3600000 · 1d→day/86400000 · 1M→month/30天 · 1y→year/366天
//    interval 缺省按窗口选:≤2h 1m;≤24h 5m;≤7d 1h;≤90d 1d;更长 1M
// ② 业务统计(一期只有收益趋势 POST /kzserver/biz/power/stationRevenueTrend)
{ stationId: string; metric?: 'inc' | 'cost' | 'net' }
// ExtResult.series:kz 返回 data 里「量名 → 升序 [{ ts, value }]」(createTime / zdValue 忽略)
// ExtResult.meta:通用历史 { bucket, agg, startTs, endTs };收益趋势 { mode, rows };统计类 key:value 结果也放这里
// 鉴权:同 TB token(X-Authorization);kz 地址 http://{ip}:8099,路径前缀 /kzserver 由 tbClient 拼
```

**实测备注(2026-09-07,`docs/联调记录/kz-接口实测-2026-09-07.md`)**:粒度只由路径段决定,`interval` 参数被 kz 忽略;非 ZD 时 `zdValue` 为 0 而非 null;缺数据的时段不补 0 直接缺点;`year` 桶只回 1 个点且 `ts` 为查询时刻;不存在的 key → HTTP 200 + `code 500 "key不存在"`(多 key 中有一个不存在整个请求失败);不支持的 agg 静默返回空。**kz 的 `tskv/**` 目前不校验 token(只查非空;`biz/**` 正常)**,「同 TB token、同权限」在同事修复前不成立(09-08 新包已修复,token 校验与 `biz/**` 同策略;尚未按实体归属过滤,见联调环境待办 ⑤b),现场部署见联调环境 §5 待办 ⑤。

归档规则(影响写回 TB 的计算结果):同事的归档服务全量采集**遥测** key、不采**服务端属性**。要画长曲线的结果写遥测(会被归档,kz 可查);只作中间量 / 状态位的结果写属性。

## 7. 注册表类型(编辑期元数据,不进 JSON Schema)

见 `registry.ts`。要点:

- `WidgetDefinition.propsSchema` 只允许 JSON Schema 子集:`string`(可 `enum` / `format: color|url|multiline`)、`number|integer`(`minimum/maximum/multipleOf`)、`boolean`、`array` of object。属性面板对这些全部无兜底生成(T3.3)。
- `WidgetDefinition.bindingSlots[]`:`{ name, valueType: number|string|boolean|series|alarms|any, required?, modes?, multiple? }`。渲染器按 `valueType` 把 Binding 结果整形后交给组件;工具按 `modes` 限制可选取数方式。
- `TemplateDefinition`:`kind: 'scaled'`(设计尺寸 + 整体缩放,大屏)或 `'grid'`(CSS grid,后台页);`slots[].area` 相应为像素矩形或 grid-area 名;`slots[].accepts` 限制可放组件;`fixed` 声明内建固定组件(告警横幅)。

## 8. 版本与变更

- `schemaVersion: 1` 覆盖一期全部。新增**可选**字段不升版本;删字段、改语义、改必填性升为 2,并在渲染器实现 1→2 迁移或明确拒绝。
- 任何契约改动:先改 `.ts` → `pnpm gen:schema` → 补 / 改测试样本 → 改本文 → 双签(冻结后)。
