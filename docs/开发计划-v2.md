## 0. 如何使用本文档

- 每个任务有唯一编号 `T<阶段>.<序号>`,格式统一为:**目标 → 交付物 → 完成标准 → 依赖 / 备注**。「完成标准」是可以被第三方核对的事实(文件存在、测试通过、某操作在镜像上得到某结果),不是「基本可用」这类描述。
- 任务前的 `- [ ]` 是进度勾选位。勾选时在同一行追加 `(完成于 YYYY-MM-DD)`,若与计划有偏差在下方缩进一行写「实际:…」。这与 `docs/生产镜像-无代码部署工具-开发计划.md` 的记录习惯一致。
- 人日估算来自架构 §11.1,本文按任务拆到 0.5 人日粒度;总量不变(YY 约 16–18 人日,同事约 3–5 人日)。
- 凡写「同事」的任务,YY 侧的责任是提供接口约定、示例数据和联调环境,不代做。

## 1. 目标、范围与前提

### 1.1 一期目标(一句话)

工程人员在部署工具里连接 TB、选模板、按槽位配组件和数据绑定、校验、预览、发布到 TB 的 `ScadaPage` 资产;同事的生产前端应用读取该资产用同一份渲染器包渲染;全过程不写代码、不重新构建前端。

### 1.2 三个里程碑(架构 §11.2)

| 里程碑 | 时间 | 定义 |
|---|---|---|
| **A** | 第 2 周末 | 手写一份 `PageConfig` JSON(含 SVG 接线图),存到镜像 TB 的 `ScadaPage` 资产,在同事应用里用真实数据渲染出来 |
| **B** | 第 3 周末 | 工程人员在工具里选模板配页面 → 发布 → 同事应用刷新可见 |
| **C** | 第 4 周末 | 一个真实项目由工程人员独立完成「规则 + 页面」上线,一期验收通过 |

### 1.3 范围内

1. 三个 npm 包:`@grid/scada-renderer`(含契约)、`@grid/tb-client`、`@grid/tbsite-compiler`(编译核心 + CLI)。
2. 部署工具编辑壳:模板槽位选择、属性面板、绑定选择器、校验、预览(含 Customer 视角)、发布(`ScadaPage` + 历史 + Relation + Customer 分配)、漂移检测、`.scadaproj` 项目文件。
3. 9–10 种只读组件 + 3 个页面模板 + 包内 `/dev` 展示页。
4. 同事应用接入:路由、读 `ScadaPage`、注入 tbClient;SVG 接线图迁入注册表(同事)。
5. 清理:删除三级取数与内嵌凭据;独立单文件大屏补登录页(保留为并行低耦合路线,架构 §4)。
6. 已完成模块补测试:元数据读取、规则编译(含 Profile 告警双轨)。
7. 一份工程人员操作说明。

### 1.4 范围外(二期,见 §10)

写操作(开关 / 按钮 / RPC / 写守卫 / 操作日志 / rpcMethods 来源)、tbClient 零依赖内核与引用计数、Storybook、Pinia、向导 TS 迁移、点表导入、自定义模板、Tauri、地图组件进注册表、kz 地址参数化。

### 1.5 前提假设(任一不成立即触发 §9 风险处置)

- 同事从 D1 起每周可投入约 2.5 个工作日,且 D1–D2 两天全程参与契约议定。
- 第 1 周内锁定一个可联调的真实站点(默认 `xrs-mirror-test` 所在的仙人山镜像数据;若换真实项目需在 D5 前定)。
- 生产镜像 TB 可写(规则链、资产、Relation、Customer 分配);有一个 CUSTOMER_USER 账号供「Customer 视角预览」验证。
- TB 版本固定 CE 4.3.1.3;不在一期内升级。

## 2. 工程结构与开发约定

### 2.1 目录

见 `dev/README.md`。pnpm workspaces,三个 `packages/*` + 一个 `apps/deploy-tool`。同事应用不入库,以 `file:` 链接开发(架构 §3「包的组织」)。

### 2.2 命名与版本

| 项 | 约定 |
|---|---|
| 包名 | `@grid/scada-renderer`、`@grid/tb-client`、`@grid/tbsite-compiler`;应用 `deploy-tool` |
| 版本 | 开发期全部 `0.x`,workspace 内 `workspace:*`;里程碑 A 打 `renderer@0.1.0` / `tb-client@0.1.0`,B 打 `0.2.0`,C 打 `1.0.0-rc.1` |
| 契约版本 | `PageConfig.schemaVersion = 1`;一期内不允许破坏性变更,新增字段必须可选 |
| 运算结果 key | 新输出统一 `calc_` 前缀;级联例外走白名单(ADR-003) |
| TB 实体标记 | 工具创建的实体 `additionalInfo.managedBy = "deploy-tool"`,`additionalInfo.version = <发布号>` |

### 2.3 现有代码的处置(架构 §9「现有代码怎么办」)

- `tb-frontend/` 在 T0.3 **复制**进 `dev/apps/deploy-tool/`,原目录从此冻结只读,里程碑 B 验收后归档(移到 `resource/legacy-tb-frontend/` 或删除,由 YY 决定)。冻结期间若必须改原目录(线上紧急修复),改动需在当日同步到 `apps/deploy-tool`。
- `tb-compiler/tbsite_compile.py` 在 T1.3 完成、同构测试通过后冻结,文件头加「已冻结,请使用 `pnpm tbsite`」注释;`test_site_pipelines.py`、`tb_gw_simulator.py` 保留可用。
- `tb-compiler/sites/*.tbsite.json` 作为同构测试的固定样本,复制到 `packages/compiler/test/fixtures/`。

### 2.4 语言与工具

- 新包:TypeScript(strict)、Vite library mode 构建、Vitest 测试、ESLint + Prettier(根统一配置)。
- `apps/deploy-tool`:现有 `Provisioner.vue`(2713 行)、`publisher.js` 保留 JS;新增模块(模板槽位 UI、属性面板、绑定选择器、发布器 v2、迁移函数)用 TS 或 `<script setup lang="ts">`。
- 状态管理:新模块 `composable + reactive()`;不引入 Pinia。
- 图表:ECharts 按需引入,只在渲染器包内;宿主不再直接依赖 ECharts。
- 样式:渲染器根节点 class 前缀 `sr-`,主题走 CSS 变量;微电网深蓝主题令牌从 `theme-microgrid-site.css` 抽为渲染器默认主题文件。

### 2.5 分支 / 提交(详见 `CONTRIBUTING.md`)

- 仓库:`dev/` 即 git 根,托管于 GitHub 私有库 `YepYepFrank/scada-deploy-tool`(2026-09-03 建),团队成员由仓库所有者邀请。
- 工作流:**Trunk-Based Development**——直接在 `main` 小步提交;跨多次提交的改动用 ≤ 2 天的短命分支 `t<任务号>-<slug>` 合回后删除;里程碑打 tag。
- 提交时机:每个任务(或可独立验证的子步)**本地验证通过后立即提交并推送**;未验证不提交。
- 提交信息:**Conventional Commits** `<type>(<scope>): <subject>` + footer `Refs: T<阶段>.<序号>`;`.githooks/commit-msg` 强制。
- 凭据不入库:`.githooks/pre-commit` 扫描暂存区,CI `secret-scan.yml` 跑 gitleaks;凭据只在 `.env.local`(模板 `.env.example`)或运行时输入。
- 克隆后执行一次 `git config core.hooksPath .githooks`。

### 5.1 PageConfig(架构 §6,原样采用)

```ts
interface PageConfig { schemaVersion: 1; template: string; theme?: string; widgets: WidgetConfig[] }
interface WidgetConfig {
  id: string; slot: string; type: string
  props: Record<string, unknown>
  bindings: Record<string, Binding>
  actions?: Record<string, Action>          // 契约保留,一期只校验 + 禁用态
}
type Binding =
  | { mode: 'ts';         entity: EntityRef; key: string }
  | { mode: 'ts-history'; entity: EntityRef; keys: string[]; window: string; agg?: 'AVG'|'MIN'|'MAX'|'SUM'|'COUNT'|'NONE' }
  | { mode: 'attr';       entity: EntityRef; scope: 'SERVER_SCOPE'|'SHARED_SCOPE'|'CLIENT_SCOPE'; key: string }
  | { mode: 'alarm';      entity: EntityRef; types?: string[] }
  | { mode: 'const';      value: unknown }
  // | { mode: 'ext'; source: string; params: Record<string, unknown> }   ← 仅当 ADR-004 选此路线时加入
type Action = { kind: 'rpc'; entity: EntityRef; method: string; confirm?: boolean }
            | { kind: 'attr'; entity: EntityRef; scope: string; key: string }
type EntityRef = { type: 'DEVICE' | 'ASSET'; id: string }
```

需议定的细节:`window` 字符串语法(建议 `^\d+(m|h|d)$`);`series` 类型的多序列如何表达——建议 `bindings.series` 允许 **数组形式** `Binding[]`(每条一序列),渲染器对 `series` 类 slot 接受单个或数组;`id` 生成规则(建议 `w-<slot>`,同槽唯一)。
