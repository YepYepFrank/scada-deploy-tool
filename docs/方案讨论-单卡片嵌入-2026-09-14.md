## 0. 一句话

页面配置里每张卡本来就是一段自包含的 JSON(`{ id, slot, type, props, bindings }`):「展现形式」= `type + props`,「数据源」= `bindings`,唯一把它绑在整页上的只有 `slot`。渲染器内部也是一张卡一张卡地解析绑定的(`resolveBindings`),只是对外只暴露了整页的 `<ScadaPage>`。

要做的是四件事,**契约 PageConfig 不加字段**:

1. 渲染器加单卡入口 `<ScadaWidget>`(§3);
2. 组件 id 改成「创建时生成一次、之后不变」(§2);
3. 每个站点多一张「卡片库」页存可复用卡(§4);
4. 工具里每张卡一个「复制引用」(§5)。

## 2. 引用方式:页面 id + 组件 id

**页面 id** = TB 上 ScadaPage 资产的 id(uuid)。重命名页面不变;她现在读 `pageConfig` 用的就是它,不改。

**组件 id**:

- 现状:编辑器生成 `<组件类型>-<槽位>`(如 `number-card-r1c1`),从旧模型迁来的页面是 `w-<槽位>`;渲染器只要求页内唯一,`validateAgainstRegistry` 已经查重复。编辑器是「一个槽位一个组件」,**没有**「移动」「复制」操作,所以现有 id 实际上已经稳定——只有工程人员把某个槽位的组件换成别的类型时才换 id(那是另一张卡,换 id 合理)。
- 改法:
  - 创建时生成 `w_` + 8 位随机 base36(`crypto.getRandomValues`),与槽位、类型都无关;
  - 换模板时同名槽位的组件原位保留、id 不变(现在就是这样,补一条测试钉住);
  - 将来加「移动 / 复制」时遵守庄说的规则:移动只改 `slot`;复制生成新 id。写进 `useEditorState` 的注释与测试,别人以后加功能时看得到。
- 已发布页面**不迁移**:旧 id 继续有效,工程人员不动那张卡它就不变。
- 要明确告诉庄的一条:**换组件类型 = 换 id**;属性、绑定怎么改都不换。

契约层面:`PageConfig` 不新增字段;`WidgetConfig.id` 的注释里「工具生成规则为 `w-<slot>`」改成描述新规则,JSON Schema 不变(pattern 仍是 `^[A-Za-z0-9_-]+$`)。知会高潮即可,不需要三方定。

## 3. 渲染器:`<ScadaWidget>`

```vue
<ScadaWidget :config="widget" :data-source="ds" theme="default" @bind-error="onErr" />
```

- `config`:一份 `WidgetConfig`,`slot` 可以没有(有也忽略)。
- 数据源:与 `<ScadaPage>` 一样——prop 优先,否则用 `provideDataSource` 注入的。她的接入方式不变(`registerBuiltins()` + `provideDataSource(tbClient)`)。
- 内部:`migrateConfigProps` → `resolveBindings`(只这一张卡)→ `<component :is="def.component" :values :errors :disabled>`。把 `ScadaPage.vue` 里「单卡渲染 + 绑定生命周期」抽成 `useWidgetRuntime(config, ds)`,整页与单卡共用同一份代码,不复制。
- 样式作用域:根节点自带 `sr-page sr-theme-<theme> sr-widget-standalone`,`--sr-*` 令牌在它上生效,她在祖先节点上覆盖令牌即可换色;`--sr-scale: 1`,不做整页缩放;`width/height: 100%` 填满她给的容器。ECharts 图表已经用 ResizeObserver 自动 resize(`widgets/_shared/echarts.ts`),不用额外做。
- 导出:`ScadaWidget`、`pickWidget(page, widgetId)`(找不到返回 `undefined`)、`useWidgetRuntime`(导出,一期不写进她的文档)。
- 版本 `0.2.0 → 0.3.0`,交付走 `pnpm pack:delivery`。

## 4. 卡片库(一期)

- **存储**:站点下**再一张 ScadaPage 资产**,名 `<站点>-卡片库`,模板 `cards`,`additionalInfo.kind: 'cards'`(工具自己的资产级标记;页面配置本身不加字段)。发布、版本、历史、客户归属全部复用现有页面机制;庄读它和读普通页面一模一样。
- **`cards` 模板**:grid 类型,4 列 × 6 行 = 24 格,任意组件,无必填槽位。满了再加 `cards-48`——模板是注册表条目,加一个不影响旧页面。
- **大屏** `site.html` 的页面列表跳过 `kind: 'cards'` 的页面,不然值班的人会看到一张 24 格的杂物页。
- **向导第 4 步**:现在只认站点的第一张页面(`loadSitePage` 取 `pages[0]`)。改成「页面 | 卡片库」两个标签,各自一份编辑器状态、各自的发布 / 版本 / 历史;第 5 步「发布页面」两张一起发(只发有改动的)。**这是本方案最大的一块改动。**
- **两种录入**:
  1. 卡片库标签里点格子放组件、配属性和绑定,与配页面完全一样;
  2. 页面编辑里选中一张卡 → 「存为可复用卡片」:深拷贝、换新 id、放进卡片库第一个空格(满了提示)。反向的「从卡片库放进页面」顺手做(拷贝、换新 id、用目标槽位)。
- **自定义的边界**:只有现有 10 种组件的属性与绑定,不提供自定义组件开发(与庄一致)。
- **跨站点复用(二期)**:卡片绑定里的实体按 ADR-002 是「按名字存、发布时解析 id」,同名设备在另一个站点会自然解析到那边;不同名就要一张映射表——这正是第 3 步「设备模板」已经在做的事(按设备类型匹配)。二期可以把卡片库做成「按设备类型模板化」的卡。一期不做。

## 5. 工具与命令行

- 第 4 步每张卡的属性面板顶部显示「引用:页面 id · 组件 id」,一键复制 JSON `{ "pageId": "…", "widgetId": "…" }` 或一段接入代码(§6 那几行)。页面还没发布时没有页面 id,提示先发布。
- `tbsite pages --site <站点> --widgets`:列出每张页面每张卡的 id / 类型 / 标题 / 绑定摘要,给她对照,也方便排查「引用断了」。

## 6. 庄侧接入与验收

```vue
<script setup>
import { ScadaWidget, pickWidget, validatePageConfig } from '@grid/scada-renderer'
// 读法不变:GET /api/plugins/telemetry/ASSET/{pageId}/values/attributes/SERVER_SCOPE → pageConfig
const page = validatePageConfig(JSON.parse(raw.pageConfig)).value
const card = pickWidget(page, 'w_3k9f2a1c')     // 页面 id + 组件 id
</script>
<template>
  <div class="my-cell"><ScadaWidget v-if="card" :config="card" /></div>
</template>
```

验收清单(她提的三条 + 补三条):

1. 曲线 / 双轴 / 仪表盘放进 rem 容器,窗口缩放时图表跟着 resize、不裁切;
2. 数字卡在最小尺寸(建议不低于 160 × 90 px 等效)下文字不溢出,`--sr-min-text` 下限生效;
3. 字体:组件里是 px + 令牌,不随她的 `html { font-size }` 变。若要跟 rem 走,她在容器上覆盖字号令牌——一期先看效果,需要再把字号令牌化;
4. 同一页 N 张卡订同一个测点,每张独立退订、互不影响(她 09-09 已验过 TbClient 逐条退订);
5. 页面在工具里重新发布后,她的页面刷新即拿到新配置(一期不推送;要热更新可订阅资产属性 `pageConfig` 的变更,二期);
6. 客户账号打开:卡片绑定的实体不在该客户下时显示「不可用」,与整页行为一致。

## 8. 想过但不做(留档)

- 一卡一个 iframe(`site.html?widget=…`):每张卡一次登录一条连接,几十张卡撑不住,样式也进不了她的页面。
- 每张卡在 TB 上单独存一个资产 / 属性:她多一次请求,我们多一套发布与同步逻辑,一页的 JSON 本来就小。
- 只给 JSON 让她自己画:等于把 10 种组件再写一遍。
- 手填引用名 / 别名字段:庄否决;真有业务编码需求再加可选 `alias`。
