# Root 规则链约定(给高潮)· 2026-09-11

**Root Rule Chain 由你维护,部署工具从 2026-09-11 起永远不写它**(YY 定)——不接线、不摘节点、不重存元数据。

## 为什么

- Root 上挂着 21 个定时器,其中有 kz 的按分 / 5 分 / 时 / 天 / 月归档触发(REST 调 `:8099/rulestaticsapi/*`)。
  TB 每保存一次规则链元数据就重启链上全部节点、定时器从头计时,可能丢一天的日归档或一个月的月归档。
- Root 的版本号已经 400+,你经常改它;工具「读出来 → 改 → 写回」会覆盖你刚改的东西。

以前工具在 Root 上加过一个节点 **`site alarms flow · xrs-mirror-test`**(转发到 `Site Alarms · xrs-mirror-test`),
现在它归你管,工具不会再动它。

## 需要你做的只有一件事

**某个站点第一次在部署工具里配了告警**,工具会建好该站点的告警链 `Site Alarms · <站点>`,
但告警链要靠 Root 把遥测转过去才会工作。这时工具的发布结果里告警这一步会报失败,文字大致是:

> 告警链「Site Alarms · <站点>」已写好,但 Root 链上还没有转发到它的节点,告警不会触发……(id xxxx)

请在 Root Rule Chain 里:

1. 加一个 **Rule Chain** 节点(`TbRuleChainInputNode`),指向规则链 `Site Alarms · <站点>`;
   名字随意,建议 `site alarms flow · <站点>`(工具按「指向哪条链」认,不看名字)。
2. 从 **Message Type Switch** 的 **Post telemetry** 连一条线到它。
3. 保存。现场在向导里点「重试失败项」即可复核。

## 站点删掉告警 / 清理站点时

工具发现 Root 上还有节点转发给这个站点的链,**只清空这条链、不删它**(删了你的 Root 会指向一条不存在的链),
并在结果里提示「已清空未删:Root 链上还有转发到它的节点,请高潮摘除后下次发布再删」。
你摘掉那个节点后,下次发布或清理会自动把空链删掉。

只读:① 核对上面那个转发节点在不在;② 第 3 步「平台上已有的配置」里列出 Root 的节点数、定时器数(只展示)。
