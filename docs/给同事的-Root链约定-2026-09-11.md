# Root 规则链约定(给高潮)· 2026-09-11

**Root Rule Chain 由你维护。部署工具可以写 Root,但只动它自己配的那一部分**——每个站点一个转发节点
`site alarms flow · <站点>`(以及从 Message Type Switch 连到它的那条 Post telemetry 线)。
你配的节点、连线、定时器,工具一律不改、不删、不挪。(YY 定;同日一度理解成「工具完全不写 Root」,已更正。)

## 工具在 Root 上会做什么

| 时机 | 动作 |
|---|---|
| 某个站点**第一次**配了告警 | 加一个转发节点 `site alarms flow · <站点>` → 该站点的告警链 `Site Alarms · <站点>`,从 Message Type Switch 的 Post telemetry 连过去;节点上带标记 `additionalInfo.managedBy = deploy-tool, site = <站点>` |
| 站点告警链改了名 | 只改自己那个节点的指向 |
| 站点**删光了**告警 / 清理站点 | 摘掉自己那个节点和连到它的线,其余节点的连线索引重排 |
| 其它任何时候(平时发布) | **不写 Root** |
| Root 上已经有别的节点(比如你手工加的)转发到该站点的告警链 | 工具不再加自己的,也不写 Root |
| 部署人员在向导第 3 步手动操作(2026-09-11 起,见下节) | 只动该站点自己那个节点 |

## 向导第 3 步里的手动操作(2026-09-11 起)

第 3 步「规则链」清单里,Root 这一行可以对**本站点自己的转发节点**做三件事,都要部署人员确认后才写,确认框里写明会重启 Root:

- **改指向**:改它转发到本站点的哪条链(下拉里只有本站点自己的链);
- **重新接线**:让它指回本站点的告警链——节点丢了就补上,指错了就改回;已经有节点(包括你手工加的)转发到告警链时不写;
- **删除**:摘掉这个节点和连到它的线。

本站点自己的链(`Site Alarms / Rollups / Revenue · <站点>`)可以在同一个清单里**删除**:告警链被本站点的节点指着时先摘节点;
摘完 Root 上还有别的节点转发给它,只清空不删。别的站点的链、你的链、Root 本身,工具一律不删不改。

写 Root 仍走同一套保护(写前核对你的部分一字不差、带 version 防覆盖)。注意:只要站点还有告警,下一次发布会把节点接回告警链。

## 怎么保证不碰你的部分

- **写之前自查**:工具把「除本站点自己节点以外的全部节点与连线」和读出来时逐字比对,一字不差才写;否则中止,不写 Root。
- **版本锁**:写 Root 时带读出来的 `version`,你恰好也在改 Root 时 TB 会回 409,工具报「Root 规则链刚被别人改过」并放弃这次写入,不会覆盖你。
- **认自己的节点**:只认带本站点标记的转发节点;09-11 之前建的(如 `site alarms flow · xrs-mirror-test`)没有标记,按约定名认。
- **删链时**:摘完自己的节点后,如果 Root 上还有别的节点转发给这条链,这条链只清空、不删(删了你的节点会指向一条不存在的链),
  结果里提示「Root 上还有别人的节点转发到它」。

## 需要你知道的副作用

TB 只能整条保存规则链,**工具每写一次 Root(接线 / 摘线),Root 上所有节点都会重启**,包括 kz 的按分 / 5 分 / 时 / 天 / 月归档定时器——
内容不变,但定时器从头计时。所以工具只在「站点第一次有告警」和「站点删光告警 / 清理」这两个时刻写 Root,平时不写。
如果你担心某次重启错过归档时点,可以约定这类操作放在归档窗口之外做。
