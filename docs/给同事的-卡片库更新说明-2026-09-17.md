## 1. 你现在就能用的:卡片库检视页

工程人员发布卡片库后,你打开

```
site.html?site=<站点标识>&cards=1
```

用你的账号登录,就是一张**检视页**:一行一张卡,

- **左栏**:用真数据渲染出来的这张卡(和你 `<ScadaWidget>` 嵌进去会看到的一样,实时刷新);
- **右栏**:数据源摘要(`value = ts SSP1_GP1_IED1.P` 这种)、订阅报错(没权限 / 实体不存在会直接写在这张卡下面)、**页面 id + 组件 id**、「复制引用」「复制接入代码」。

不加 `&cards=1` 进去是页面列表,列表里也有「检视卡片库」按钮。卡片库本身仍然不会出现在页面列表里(按资产 `additionalInfo.kind === 'cards'` 区分,和 09-14 说的一样)。

镜像上现在还没有发布过的卡片库(工程人员配完发布才有)。要先试,可以拿 09-14 说明 §4 里那几张已发布页面的卡,读法与引用方式完全一样。

## 2. 工具那边怎么给你卡(你不用操作,知道流程就行)

- 第 4 步「卡片库」标签现在是一张**列表**,一行一张卡,左栏组件、右栏「前端怎么引用」(页面 id + 组件 id、复制按钮)。工程人员把引用复制给你就是 `{ "pageId": "...", "widgetId": "w_xxxxxxxx" }`。
- 编辑一张卡是**单卡编辑**(不再有整页画布),配法和配页面里的一个组件一样;新建、删除都在列表上。
- 「预览卡片库(实时值)」和上面的检视页是同一个东西,工程人员发布前先自己核一遍数值和数据源。
- 页面和卡片库都在第 5 步「一键发布」时一起写进平台(先规则、后页面、再卡片库);工程人员改完不会有「页面发了卡片库没发」的情况。
- 组件 id 规则不变:创建时生成一次,改属性 / 绑定不变;删掉一张卡它的引用就失效,工具删除时会提醒工程人员。

## 3. 渲染器包里已经改了、下一个包才会带给你的

| 改动 | 对你的影响 |
|---|---|
| **组件右上角「⤢ 放大」**(0.3.2):`<ScadaPage>` / `<ScadaWidget>` 每个组件悬停出现放大按钮,点开铺满视口再渲染一份(共用同一份值,不新建订阅),✕ / Esc 关闭 | 默认开着。你的页面如果自己有放大逻辑或不想要,传 `:expandable="false"`;放大层 `position: fixed; z-index: 1000`,你有更高层级的弹窗抽屉要留意。事件 `expand(widgetId \| null)` |
| 卡片库模板容量 24 → 48(未发布) | 你读到的 `pageConfig` 里槽位名多了 `c25…c48`,你只按组件 id 取卡,无感 |
| 态势总览台 `g1` 不再必填(未发布) | 只影响工具里的校验提示,渲染无变化 |

这三条都**不改契约**(`schemaVersion` 仍是 1,`PageConfig` 没有新字段),所以你现在这个包照常用;什么时候换包我们再给 tarball + 交付清单。

## 4. 验收还是那 6 条

09-14 说明 §5 的 6 条验收没变(rem 容器下图表 resize、最小尺寸、字体、多卡同测点、重发布后刷新、客户账号「不可用」)。检视页正好可以当对照:你嵌进去的卡和检视页左栏长得不一样,就是接入的问题;检视页右栏有报错,就是数据源 / 权限的问题。
