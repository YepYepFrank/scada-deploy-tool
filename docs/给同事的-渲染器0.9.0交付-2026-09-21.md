## 2. 你要做的:tbClient 支持绝对时间区间(只有这一处必须改)

```ts
// @grid/tb-client 0.0.3
interface AbsoluteRange { from: number; to: number }          // 毫秒,from < to
type TimeRange = WindowLiteral | string | AbsoluteRange       // '24h' 或 { from, to }

getHistory(entity, keys, window: TimeRange, agg?): Promise<Record<string, TsPoint[]>>
interface ExtQuery { source; window?: string; range?: AbsoluteRange; interval?; params }   // range 给了就以它为准
```

包里给了现成的换算函数,`getHistory` 开头换成这一句就行(我们的 `LegacyDataSource` 就是这么写的):

```ts
import { resolveTimeRange } from '@grid/tb-client'
const { startTs, endTs } = resolveTimeRange(window)   // 字面量 = 到现在为止的最近 N;绝对区间原样;from ≥ to 抛错
const ms = endTs - startTs                            // 桶宽照旧按区间长度选
```

kz 通用历史(`ext`)同理:`query.range` 有值就用 `range.from / range.to` 当 `startTs / endTs`,没有才按 `window` 算。

几点说明:

- 渲染器**只有在配置 / 上下文给了绝对区间时**才会这样调。没改之前,只用「最近 N」的页面不受任何影响;用到绝对区间的曲线会在 `getHistory` 里报错并显示「数据不可用」。
- **绝对区间只拉历史,不追加实时**(区间是死的,往里追加新点没有意义)。「最近 N」照旧是「拉历史 + 订阅追加」。
- TB 只保留 3–7 天原始遥测。历史数据页要看更早的,绑定要用 `ext`(kz 归档),它同样支持跟随上下文和绝对区间。
- **历史告警不在这一期**:`alarm` 绑定给的是「当前活动告警全集」,没有时间范围的概念。历史告警页先保留你现在的实现;要配置化得给 `DataSource` 加一个查询方法,放到第 3 批和「实体集合」一起定。

## 3. 怎么用

### 3.1 配置长什么样(工程人员在部署工具里点出来,不用手写)

```json
{
  "id": "w_3k9f2a1c", "type": "line", "slot": "g1",
  "props": { "title": "趋势" },
  "bindings": {
    "series": [{
      "mode": "ts-history",
      "entity": { "source": "context", "key": "selectedDevice", "type": "DEVICE",
                  "fallback": { "type": "DEVICE", "id": "样例设备UUID", "name": "1# PCS" } },
      "keys":   [{ "source": "context", "key": "selectedMeasurePoint", "fallback": "P" }],
      "window": { "source": "context", "key": "timeRange", "fallback": "24h" }
    }]
  }
}
```

- 三样可以各自跟随、各自写死、随便混:只跟随设备、测点写死 `"P"`、窗口写死 `"24h"` 是最常见的。
- **只有显式写了 `source: "context"` 的地方才会被替换**,固定绑定(站点汇总资产)永远不动。
- 自定义键:`{ "source": "context", "key": "custom.selectedTu" }` ↔ 上下文里的 `custom: { selectedTu: … }`。
- `type` 填了就校验:上下文给的是 ASSET 而绑定要 DEVICE → 那张卡显示错误态,不去订阅。

### 3.2 宿主给上下文

```ts
import { provideBindingContext, type BindingContext } from '@grid/scada-renderer'

const ctx = reactive<BindingContext>({
  selectedSite: null,                     // { type: 'ASSET' | 'DEVICE', id, name? }
  selectedDevice: null,                   // { type: 'DEVICE', id, name? }
  selectedMeasurePoint: null,             // 'P' 或 { key: 'P', label: '有功功率', unit: 'kW' }
  timeRange: '24h',                       // '24h' 或 { from, to }(毫秒 / ISO 字符串 / Date 都收)
  custom: {},                             // custom.selectedTu 之类
})
provideBindingContext(ctx)                // 整页共享:下面所有 <ScadaPage> / <ScadaWidget> 都用它
```

```vue
<!-- 单卡嵌入 / 测试页 / 局部覆盖:props 优先于 provide -->
<ScadaWidget :config="card" :binding-context="ctx" />
<ScadaPage :config="page" :binding-context="ctx" />
```

设备测试页改造后大致这样,`buildDeviceTestWidgets` 可以删掉:

```vue
<script setup>
const ctx = reactive({ selectedDevice: null })
const onTreeSelect = node => (ctx.selectedDevice = { type: 'DEVICE', id: node.id, name: node.name })
// cards:从卡片库页 pickWidget 出来的几张卡,绑定里写的是 source: 'context'
</script>
<template>
  <DeviceTree @select="onTreeSelect" />
  <div v-for="c in cards" :key="c.id" class="cell"><ScadaWidget :config="c" :binding-context="ctx" /></div>
</template>
```

把曲线换成表格 / 仪表盘:工程人员在工具里改卡片库、重新发布,你的代码不动。
卡片库「检视」页和「复制接入代码」里会标出每张卡**需要哪些上下文键**;运行时也能问:`widgetRef.value.contextKeys`(`<ScadaPage>` 同)。

### 3.3 行为

| 情形 | 行为 |
|---|---|
| 上下文里被引用的键变了 | **只重订引用了它的组件**,固定绑定的卡订阅不断、数值不闪。同一 tick 连改几个键只重订一次;同一设备重复赋值(新对象、同 id)不重订 |
| 键为 null / undefined,`whenMissing` 缺省(`empty`) | 卡片框 + 「未选择设备 / 站点 / 测点 / 时间范围」,不请求、不订阅、不抛 `bindError`。该卡的 `.sr-widget` 节点上有 `data-ctx-state="empty"` |
| `hide` | 整张卡 `display: none`(`<ScadaWidget>` 连根节点一起),你的容器自己决定要不要收起 |
| `error` | 错误态 + `bindError(widgetId, '(context)', message)` |
| `fallback` | 用 `fallback` 去订阅 |
| 类型不符 / 形状不对 / 时间范围非法(`from ≥ to`、`'上周'`) | 错误态 + `bindError`,不订阅 |
| 当前用户无权访问上下文给的实体 | 走现有 `onError` → 「数据不可用」,与固定绑定一致 |
| 一张卡里有几处引用、同时缺 | 整张卡按最重的处理(`error` > `hide` > `empty`)——半张有数半张空着更让人困惑 |
| `design` 态 | 不变:用 sampleData,不订阅、不看上下文 |
| 只改了 props(标题 / 单位),绑定没变 | **不再重订**(以前配置一变就全部退订重建) |

## 4. 联动:`widget-event` 补齐了

渲染器**不改上下文**。组件被点了就抛事件,你收到后自己改 `ctx`,引用它的卡就跟着换:

| 组件 | `name` | `detail` |
|---|---|---|
| 任何组件(整卡) | `click` | `{ entity? }` —— 该卡只绑了一个实体时给出(已是解析后的具体实体) |
| table | `row-click` | `{ index, label, key, entity? }` |
| alarm-list | `alarm-click` | `{ alarm, entity }`(`entity` = 告警来源) |
| sld(原有) | `node-click` | `{ nodeId, name?, entity?: { type, name, id? } }` |

```ts
function onWidgetEvent(ev) {
  if (ev.name === 'row-click' && ev.detail?.entity?.id) ctx.selectedDevice = ev.detail.entity
  if (ev.name === 'node-click' && ev.detail?.entity?.id) ctx.selectedDevice = ev.detail.entity   // 接线图里点设备
}
```

细粒度事件(`row-click`)先抛,随后还会有一个整卡的 `click`;不关心就忽略。design 态不抛。
「在配置里声明点击后做什么」(跳转 / 弹窗 / 改上下文)放第 3 批,先让事件通路走顺。

## 5. 订阅合并 / 引用计数(在你的 tbClient 里)

位置只能在 DataSource 实现里:一页放 N 张 `<ScadaWidget>` 就是 N 份独立的绑定运行时,渲染器这层看不到彼此。
我们自用的 `LegacyDataSource`(包里 `@grid/tb-client` 的 `legacy-adapter`)可以直接参照:

- 一次 `subscribeTs / subscribeAttr` 是一个**逻辑订阅**;发给 TB 的一条命令(一个 `cmdId`)下可以挂多个逻辑订阅。
- 同一 tick 内的订阅按「种类 + 实体类型 + 实体 id + scope」分组,keys 取去重并集,一组一条命令;整批按 24000 字节分片(TB 入站单条上限 32768)。
- 回推按 key 分发;命令下成员全部退订后才向 TB 发 unsubscribe;同一 tick 里先退后订;没有任何订阅时关 WS;重连时重放全部存活的逻辑订阅。
- **已知不足**:只在同一批内合并,不会往已发出的命令里追加 key。要跨时间去重(曲线已订了 `P`,后来数字卡又订 `P`),
  得在逻辑层按「实体 + key」做引用计数,并把缓存的最新值当作后来者的首包。换设备是「一批退订 + 一批订阅」,同批合并已经覆盖得到。
