## 1. 页面菜单是什么

现在你的宿主是 `/scada/:assetId`:**URL 里给哪张页面的资产 id,就渲染哪一张**。
一个站点通常有好几张组态页面(总览、配电房、储能、报表……),现在切页只能改地址栏。

页面菜单就是把「这个站点下有哪几张页面」列出来,做成顶栏 / 侧栏里可以点的一排,
点一下换一张。就是大屏左上角那种「总览 | 配电房 | 储能」的东西。

> 注意区分:你 demo 模式(`/scada/demo`)里那个下拉框是**一个 `.scadaproj` 文件内部**
> 的多页切换,数据来自本地文件。这里要做的是**从 ThingsBoard 上查**当前站点挂了哪些
> 页面资产。两者不是一回事。

## 2. 为什么要做

三个理由,按重要性:

1. **不做就没法交付给现场。** 工程人员在部署工具里给一个站点发布 3 张页面,运维和
   值班员打开大屏只能看到 URL 里写死的那一张,其余两张等于不存在。
2. **它是客户权限验证(T3.10)的前置。** 验收标准是「用 CUSTOMER_USER 登录,**只见
   分配站点的页面**」。没有菜单,这句话没有东西可验——现在没人能看见「页面列表」这个
   概念。所以 T3.10 卡在这一项后面。
3. **它是里程碑 A 之后唯一还开着的宿主缺口。** 主链路(读配置 → 注入数据源 → 渲染)
   09-09 已经验过了,9 个组件 8 种、数据实时。只剩这一项。

## 3. 数据是怎么存的

部署工具发布页面时,会在 ThingsBoard 上建一个 **`ScadaPage` 类型的资产**,页面配置
放在它的 `SERVER_SCOPE` 属性 `pageConfig` 里(你已经在读这个)。同时把这个页面资产
**挂到站点资产下面**,关系类型是 `Contains`:

```
站点资产(type = tbsite)
  └─ Contains ─→ ScadaPage 资产 ①   ← 页面配置在它的 pageConfig 属性里
  └─ Contains ─→ ScadaPage 资产 ②
  └─ Contains ─→ ScadaPage 资产 ③
  └─ Contains ─→ 其它资产            ← 有别的东西,见下面的坑
```

所以菜单 = **查站点资产的 `Contains` 关系,取里面 type 为 `ScadaPage` 的那些**。

### 三个坑,先说在前面

**① `Contains` 底下不只有页面。** 站点下还挂着汇聚资产之类的东西。镜像上
`xrs-mirror-test` 有 4 条 `Contains`,其中 3 条是 `ScadaPage`,第 4 条是
`xrs-mirror-test-agg`(type `tbsite-agg`)。**必须按 `type === 'ScadaPage'` 过滤**,
不然菜单里会冒出一个点不开的条目。

**② `/relations/info` 不够用。** 你 `api.js` 里现成的 `getRelationInfo` 走的是
`/relations/info`,它只多给一个 `toName`,**不给资产的 `type`**——过滤不了上面那一条。
所以要么按 id 逐个 `GET /asset/{id}` 拿 type,要么用下面第 4 节推荐的两次请求法。
(另外那个函数写死了 `fromType: "DEVICE"`,站点是 ASSET,得改。)

**③ 菜单文字用 `label`,不用 `name`。** `name` 在 TB 里必须唯一,部署工具默认拼成
`<站点> · <标题>`,不好看;`label` 才是工程人员填的展示名。取 `label || name`。

## 4. 推荐写法:两次请求

思路:**先按类型列出当前身份能看到的所有 `ScadaPage`(一次),再用站点的 `Contains`
关系 id 求交集(一次)**。避免逐个资产查 type 的 N+1,而且 `?type=` 这一层过滤是
TB 服务端做的。

```js
// src/services/scadaPages.js
import request from '@/core/request'

const SCADA_PAGE_TYPE = 'ScadaPage'

/** 当前登录身份:租户看租户全部,客户只看分给自己的 —— 权限过滤交给 TB,前端不判断 */
async function assetsBase() {
  const me = await request.get('/auth/user')
  return me.authority === 'CUSTOMER_USER'
    ? `/customer/${me.customerId.id}/assets`
    : '/tenant/assets'
}

/** 分页拉完 */
async function pagedAssets(base, params) {
  const out = []
  for (let page = 0, hasNext = true; hasNext && page < 20; page++) {
    const r = await request.get(base, { params: { ...params, pageSize: 100, page } })
    out.push(...r.data)
    hasNext = r.hasNext
  }
  return out
}

/**
 * 站点下的页面菜单项。
 * @param {string} siteName 站点资产名,如 'xrs-mirror-test'
 * @returns {Promise<Array<{id, name, label, version}>>} 已按名称排序
 */
export async function listSitePages(siteName) {
  const base = await assetsBase()

  // ① 当前身份能看到的所有 ScadaPage
  const all = await pagedAssets(base, { type: SCADA_PAGE_TYPE })

  // ② 站点资产 → Contains 关系 → 取交集
  const found = await pagedAssets(base, { textSearch: siteName })
  const site = found.find((a) => a.name === siteName)
  if (!site) return sortPages(all.map(toItem))    // 看不到站点资产:退回「全部可见页面」

  const rels = await request.get('/relations', {
    params: { fromId: site.id.id, fromType: 'ASSET', relationType: 'Contains' }
  })
  const ids = new Set(
    (rels ?? []).filter((r) => r.to?.entityType === 'ASSET').map((r) => r.to.id)
  )
  return sortPages(all.filter((a) => ids.has(a.id.id)).map(toItem))
}

const toItem = (a) => ({
  id: a.id.id,
  name: a.name,
  label: a.label || a.name,              // 菜单显示 label
  version: a.additionalInfo?.version ?? null
})
const sortPages = (list) =>
  list.sort((a, b) => a.name.localeCompare(b.name, 'zh-Hans-CN'))
```

接到路由上:菜单项点击 → `router.push('/scada/' + item.id)`,你现有的
`/scada/:assetId` 一行都不用改。

### 站点名从哪来

三种,选一种就行:

- **配置里写死**(最省事):放进 `src/core/entityIds.json`,和你现在放
  `PRIMARY_DIAGRAM` / `Report_List` 是一个做法。单站点部署这样就够了。
- **路由参数**:加一条 `/scada/site/:siteName`,进来先列菜单再打开第一张。
- **从当前页面反查**:`GET /relations?toId=<页面资产id>&toType=ASSET&relationType=Contains`
  拿到父级站点,再列兄弟页面 —— 这样 `/scada/:assetId` 不用带站点名也能出菜单。
  **这一条我没验成**(写文档时镜像掉线了),TB 有这个反查接口,但用前你自己先试一次。

### 一个页面都没有时

不要显示空菜单。当前身份看不到任何 `ScadaPage` 时,给一句明确的话:

> 当前账号看不到任何页面:请让管理员把 ScadaPage 资产分配给你所属的 Customer。

这正是 T3.10 要验的那种情况——权限没配好和「真的没有页面」看起来一样,得说清楚。
