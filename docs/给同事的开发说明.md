## 0. 一分钟看懂整体

我们在做一个「0 代码配大屏」的工具。工程人员在工具里选模板、往槽位里放组件、从设备树里点选数据,点发布,页面配置(一份 JSON)就写进 ThingsBoard(下面简称 TB)。你们的应用只要读出这份 JSON,交给我们的**渲染器**组件,页面就显示出来了。

三块东西、三个人:

| 块 | 谁做 | 是什么 |
|---|---|---|
| 部署工具 + 渲染器(`@grid/scada-renderer`) | YY | 配页面的向导 / 编辑器;一个 Vue 组件 `<ScadaPage>`,给它 JSON 和数据源就能画出整页 |
| TbClient(数据源) | 庄艳芹 | 一个实现了 `DataSource` 接口的类,负责从 TB 拿实时值、历史、属性、告警,以及调 kz。**留在你的应用仓库里**,用你现有的 request.js / websocket.js |
| kz 扩展服务 + 告警 + 命名 | 高潮 | 归档数据查询接口;告警判定体系;TB 上的资产 / 遥测命名规则 |

进度:工具和渲染器这边到里程碑 B 的东西已经做完并在镜像 TB 上验证过(向导配页 → 发布 → 独立大屏能看)。现在等你们两边接上。

## 1. 已经定下来的事(按主题)

### 1.1 页面配置存在 TB 的哪里(对齐 + YY 定)

宿主应用读页面就靠这几条,请照此实现:

| 项 | 值 |
|---|---|
| 资产类型 | `ScadaPage`(每页一个 Asset) |
| 页面配置 | 该资产的 SERVER_SCOPE 属性 `pageConfig`,JSON 字符串 |
| 历史版本 | 属性 `pageConfigHistory`,数组,最近 10 版 |
| 标记 | `additionalInfo.managedBy = "deploy-tool"`、`additionalInfo.version = 发布号` |
| 归属 | 关系:站点资产 `Contains` → ScadaPage 资产 |
| 谁能看 | ScadaPage 资产分配给站点所属的 Customer;**不再用 Public 客户**(旧大屏靠 Public 匿名读的路径已删) |

宿主怎么找页面:查站点资产的 `Contains` 关系,挑出类型是 `ScadaPage` 的资产,就是菜单;进入某页 = 读它的 `pageConfig` → `JSON.parse` → 交给 `<ScadaPage>`。

### 1.2 页面配置长什么样(对齐)

只需要知道形状,不需要你们手写:

```
PageConfig { schemaVersion: 1, template, title?, widgets: [ { id, slot, type, props?, bindings } ] }
```

`bindings` 是「组件的某个数据口 → 从哪取数」,六种取法:

| mode | 意思 | 走 DataSource 的哪个方法 |
|---|---|---|
| `ts` | 实时值,订阅 | `subscribeTs` |
| `ts-history` | 短窗口历史 + 追加实时(≤ 3 天) | `getHistory` 再 `subscribeTs` |
| `attr` | 属性 | `subscribeAttr` |
| `alarm` | 活动告警 | `subscribeAlarms` |
| `const` | 写死的值 | 不取数 |
| `ext` | kz 归档数据(≥ 3 天窗口或按天 / 月 / 年统计) | `ext()` |

实体引用在 JSON 里是 `{ type: 'DEVICE' | 'ASSET', id, name? }`,**渲染器只认 id**,`name` 只是给人看的。

### 1.3 实体「按名字存,按 id 发」(YY 定,ADR-002)

工具的项目文件里实体按名字存(为了能换 TB 实例重放、能 git diff),发布时按「类型 + 名称」查成 id 写进 TB。**对你们的影响只有一条:设备 / 资产改名后,页面重新发布会报「解析不到」**,所以改名要提前说(见 §4 第 5 条)。

### 1.4 告警怎么做(对齐,ADR-001)

高潮那边的体系:告警模板 JSON 存在资产上 → TB 规则链里的节点读它判定 → 写 TB 告警表。我们的决定:

- 一期工具**不动你们的体系**,也**不往设备模板(Device Profile)写任何规则**。工具自己生成一条「站点告警规则链」,同样写 TB 告警表;页面上的「告警列表」组件读 TB 告警表,两边的告警都能看到。
- 通讯中断用 TB 自带的设备离线判定,沿用你们现有设置,工具不另做。
- 二期加一个「把工具里的阈值告警导出成你们的 JSON 格式」,方便你们导入或核对。

### 1.5 命名与归档(对齐,ADR-003)

- 工具写回 TB 的计算结果一律带前缀 `calc_`。已核对你们的 KEY 清单,和 `REALTIME_* / HIST_* / tsXxx / histXxx / GFFD_ …` 都不重叠。
- 高潮确认:归档服务**全量采集遥测 key,不采服务端属性**。所以我们:要画长曲线的结果写遥测(会被归档,kz 可查),只当中间量 / 状态位的结果写服务端属性。
- 我们的规则链不会触发你们的计算,你们的也不会触发我们的。
- 2026-09-06 起镜像上已经在跑:`xrs-mirror-test-agg.calc_totalP`(32 台 IED 总有功)、每台 IED 的 `calc_pqSum`、两台代表间隔的 `calc_PAvg5m / 1h / 1d`。工具产生的告警会沿 Contains 关系传播到站点资产 `xrs-mirror-test`,页面「告警列表」绑站点资产即可。

### 1.6 长期数据走 kz(对齐,ADR-004)

关键事实:**TB 只保留几天原始遥测**,长期数据在归档表里,由 kz 提供查询。所以:

- 页面上 ≤ 3 天的曲线用 TB(`ts-history`);更长的窗口、按天 / 月 / 年的统计,渲染器调 `DataSource.ext()`,由 TbClient 去调 kz。
- kz 通用历史接口(按实体 + key 查归档表,粒度是路径段)已经在我们的预案 `LegacyDataSource` 里实现,TbClient 照抄即可,见 §4.1。

### 1.7 暂缓的(YY 定,2026-09-04)

- SVG 接线图组件和「D 部分」接入方式一期暂缓,`main` 槽位先放图片组件。
- 一条 WebSocket 复用、订阅引用计数去重:**不是验收项**,做不做随你。

## 2. 给庄艳芹:TbClient 要做什么

### 2.1 分工(对齐,第二轮 4.4)

TbClient 留在你的应用仓库,直接 import 你的 `request.js` / `websocket.js`,不复制到我们这边。用 JS 写可以,`.d.ts` 由 YY 按接口手写并随包发布。

我们的包 `@grid/tb-client` 只放三样:接口类型 `DataSource`、临时预案 `LegacyDataSource`(你的版本到位后删)、一致性测试套件。

### 2.2 接口(对齐,契约 §4)

```ts
interface DataSource {
  readonly status: 'connecting' | 'live' | 'offline'
  onStatus(cb): Unsubscribe
  subscribeTs(entity, keys, cb, onError?): Unsubscribe
  subscribeAttr(entity, scope, keys, cb, onError?): Unsubscribe
  subscribeAlarms(entity, types | undefined, cb, onError?): Unsubscribe
  getHistory(entity, keys, window, agg?): Promise<Record<string, TsPoint[]>>
  getLatest(entity, keys): Promise<Record<string, TsPoint | null>>
  ext(query: ExtQuery): Promise<ExtResult>
}
// TsPoint = { ts: number, value: number | string | boolean | null }
// ExtQuery = { source: 'kz', window?, interval?, params }  ExtResult = { series: Record<string, TsPoint[]>, meta? }
```

用人话说,每个方法要做到:

| 方法 | 要求 |
|---|---|
| `subscribeTs` | 订阅后**第一次回调就要带当前值**(TB 的 WS 首包本来就推);之后每次推增量。返回取消函数 |
| `subscribeAlarms` | 每次回调给「当前活动告警全集」,渲染器整体替换,不做增量 |
| `getHistory` | 按窗口自动选聚合:≤2h 原始点;2h–24h 每 5 分钟平均;24h–7d 每小时;>7d 每天。结果按时间**升序** |
| `getLatest` | 不存在的 key 返回 `null`,不要报错 |
| 值归一化 | TB 给的都是字符串:`"44.851"` → 44.851,`"true"` → true;非数值串原样保留;不存在的 key(WS 首包 `[[ts, null]]`、REST `{value: null}`)都归一成 `null` |
| `status` | 连接状态当前值 + `onStatus` 回调;不依赖 Vue |
| `onError` | 订阅被 TB 拒绝时回调**一次**(典型:客户账号订阅了没分配给它的设备,WS 回 `errorCode ≠ 0`,告警 REST 回 403)。渲染器据此把组件标成「不可用」,否则就一直空着。T3.10 的验收要求「明确错误而非静默无数据」,就是这条 |
| `ext` | 曲线类结果放 `series`(量名 → `[{ts, value}]`),站点数 / 装机容量这类 key:value 放 `meta`。通用历史(按实体 + key 查 kz 归档表,粒度是路径段)和收益趋势两种,都可以照抄我们预案里的实现 |
| token | **由你的应用管**。TbClient 只接一个 `getToken()`,登录、401、刷新都在你现有的 request.js 里,不要在 TbClient 里再存密码或另起登录 |

### 2.3 真数据上踩过的坑(照着走就不会再踩)

- **退订命令必须带 `entityType` / `entityId`**。只发 `{cmdId, unsubscribe: true}`,TB 会当成关闭整个会话,之后这条连接上所有命令都回 `Session meta-data not found!`。
- REST 历史接口返回的是**降序**,要翻成升序再交出去。
- 同一个 key 会被同一页里多个组件重复订阅,各自退订不能影响别人。

### 2.4 怎么验收(对齐)

在你的仓库里装 `@grid/tb-client`(tarball 或私有源,文件名与包内 `build-info.json` 都带提交号,见 §3.1)和 vitest ≥ 2,写一个测试文件:

```ts
import { describeDataSourceConformance, FakeTb, FakeSocket } from '@grid/tb-client/testing'
import { TbClient } from '../src/tb-client'

describeDataSourceConformance('TbClient', () => {
  const tb = new FakeTb()   // 内存版 TB,含上面那些坑
  const ds = new TbClient({ baseUrl: 'http://tb', getToken: () => tb.token, fetchImpl: tb.fetch, WebSocketImpl: FakeSocket })
  return { ds, tb }
})
```

15 条用例过了就算接上了(含无权实体 onError、kz 收益趋势与 kz 通用历史)。

## 4. 给高潮:kz、告警、命名

### 4.1 kz 通用历史接口(已定稿,第三轮)

按你的接口汇总文档:

```
GET http://{ip}:8099/kzserver/tskv/{minute|minutefive|hour|day|month|year}/telemetry/{entityType}/{entityId}/values/timeseries
    ?keys=P,Q&startTs=<ms>&endTs=<ms>&interval=<ms>&agg=AVG|MAX|MIN|ZD
头:X-Authorization: Bearer <TB token>
返回:{ code: 200, msg, data: { <量名>: [{ ts, value, createTime, zdValue }] } }
```

我们只用 `ts / value`。渲染器那边的 `{ entity, keys, agg? }` + 窗口 + 粒度由 tbClient 映射成这个请求(粒度 → 路径段),我们的预案已实现,TbClient 照抄。**不需要你再改接口。**

**2026-09-07 在镜像上实测过一遍**(记录在 `docs/联调记录/kz-接口实测-2026-09-07.md`),六个粒度桶都能用,三点和文档不一样、你知道一下即可:`interval` 参数实际被忽略(粒度只看路径);`year` 桶只回 1 个点、`ts` 是查询时刻;非 ZD 时 `zdValue` 是 0 不是 null。

**一条要你处理的**:`/kzserver/tskv/**`(六个粒度桶的通用历史)不校验 token——`Bearer nope`、改过签名的 JWT、过期 JWT 都返回完整数据,客户 token 也能读没分配给它的设备;而 `/kzserver/biz/**` 是正常的(假 token 回 `401 token失效`)。看起来是 `tskv` 控制器漏挂了鉴权拦截器,把 `biz` 那套挂上去即可;客户账号再按 TB 的实体归属过滤。修好之前,现场的 8099 请只走同机反代、不要对客户网络开放。**09-07 晚回复**:是之前配置错了,会改成和 `/biz` 一样的鉴权策略——改完说一声,我们用 `kz-auth.live.ts` 复测(假 / 篡改 / 过期 token 都应被拒)。**09-08 复测**:新包已装到镜像,token 校验与 `/biz` 一致,通过。**还剩一小步(不急)**:`tskv/**` 现在只验 token 真假,不看这个 token 能不能访问路径里的实体——客户账号读没分配给它的设备,TB 回 403、kz 仍回全量数据。建议在 `tskv` 拦截器里用同一 token 查一次 TB `/api/{type}/{id}`,非 2xx 就拒;记录在 `docs/联调记录/kz-更新部署-2026-09-08.md` §3。
