# 向导里「去忙了一会儿,回来实时数据全没了」· 排查与修复(2026-09-21)

**现象**(同事反馈):在部署工具里编辑到一半去忙别的,回来发现工具里的实时数据全没了。

## 结论

不是连接不稳,是**登录令牌过期后工具不会续期**。

| 事实 | 怎么确认的 |
|---|---|
| TB 的 access token **2.5 小时**过期(9000 s),refresh token 7 天、每次刷新重新起算 | CT110 上登录后解 JWT 的 `iat / exp` |
| `POST /api/auth/token { refreshToken }` 能换回全新的一对 | CT110 实测 HTTP 200,新 access 9000 s、新 refresh 7 天 |
| 向导、编辑器、预览登录一次后**一直用同一个 token**,没有任何续期 | 全仓只有独立大屏薄壳(`standalone/session.ts`)有续期;向导 `api()` 收到 401 直接抛错 |
| 预览的数据源 `getToken` 是闭包,捕获的是**创建那一刻的 token 字符串** | `PreviewPane.vue`:`make(base, () => token)` |
| WS 带一张 TB 不认的 token:**握手成功,3 ms 后被服务端关闭**,`code=1011 reason="JWT Token expired"` | CT110 实测 |

串起来:登录满 2.5 小时后,REST 一律 401;WebSocket 只要断过一次(电脑休眠 / 锁屏 / 网络抖动 / 代理空闲超时),
数据源就拿着那张过期的票去重连——TB 让它连上、随即踢掉,数据源 3 秒后再试,如此往复,永远订不上数据。
页面上看到的就是「实时数据全没了」,连接状态在「实时 / 离线」之间来回跳。

「去忙点别的」正好凑齐两个条件:时间过了 2.5 小时;电脑休眠或标签页退到后台,WS 断过。

## 修复

- 新增 `api/tb-session.ts`:把已有的 `TokenKeeper`(纯逻辑、有单测)包成向导用得上的会话——
  `freshToken()` 保证给出的 token 至少还能用 10 分钟;每 4 分钟心跳;页面回到前台 / 网络恢复时立刻检查
  (休眠期间定时器是停的);续不下去(超过 7 天 / 被吊销)才提示重新连接。
- 向导 `api()`:每次请求前要一个没过期的 token;收到 401 强制换一次再试。refresh token 只在内存,不落盘。
- 编辑器:token 归向导管,每次请求前向向导要;向导续期时**不重读元数据树**(只是换了张票)。独立打开的编辑器自己续期。
- 预览:数据源每次(重)连都来要新 token,不再捕获字符串;token 续期**不拆订阅**(数据源跟着「身份」换,不跟着 token 换)。
  Customer 视角自己登录的那份同样续期。

## 没确认的

TB 会不会在 token 到期那一刻**主动**踢掉一条还活着的 WS——没等 2.5 小时去验。不影响结论:不管它踢不踢,
修复后重连拿到的都是新票。
