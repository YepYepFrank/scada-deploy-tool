# 方式 A 演练:nginx 同域单端口反代 · 2026-09-08

> 目的:把 `前端交付部署指南-v2.md` 方式 A 的配置在 TB 镜像容器里原样跑一遍,证明「前端 + TB REST/WS + kz 三者同源」的部署可用,顺便用 `auth_request` 在反代层兜住 kz 的实体归属过滤缺口(联调环境待办 ⑤b)。同一提交里向导「记住登录」改为只记账号。

## 1. 环境

| 项 | 值 |
|---|---|
| 主机 | LXC 111(`tb-mirror`,Debian 12),TB `127.0.0.1:8080`,kz `127.0.0.1:8099` |
| nginx | `1.22.1`(`apt-get install nginx`,本次新装),站点 `/etc/nginx/sites-available/gridops` → `sites-enabled/`,监听 **8088**(80 留给 nginx 默认页,不影响 TB) |
| 静态目录 | `/var/www/gridops` = `pnpm -F deploy-tool build` 的 `dist/`(4.8 MB,tar 经 SFTP + `pct push` 上去) |
| http 级配置 | `/etc/nginx/conf.d/upgrade-map.conf`:`map $http_upgrade $connection_upgrade { default upgrade; '' close; }` |
| 入口 | `http://192.168.20.61:8088/provisioner.html`、`.../site.html?site=xrs-mirror-test`(不带 `base` / `kz`) |

配置正文与指南 v2 方式 A 一致(指南已按本次演练更新):`/api/` 反代 8080 带 `Upgrade` / `Connection $connection_upgrade`、`proxy_read_timeout 3600s`;`/kz/` 先 `auth_request /_tb_auth`,再 `rewrite ^/kz(/.*)$ $1 break` 转 8099;`/_tb_auth` 是 `internal`,把请求的 `X-Authorization` 原样转给 TB `/api/auth/user`,非 2xx 即 401。

## 3. 结论与现场注意

- 方式 A 可用,文档里的配置就是跑通的配置;现场只需改 `root`、`listen`、两个上游地址。
- `auth_request` 这一道让「没有 TB 登录态的人」完全碰不到 kz;但**它只验 token 有效,不验实体归属**(客户 token 仍能读任意设备的归档,同 ⑤b),真正的归属过滤还得 kz 自己做。现场 8099 仍不得对客户网络开放。
- 静态目录用 `tar` 从 Windows 打包时要 `--force-local`(否则 `C:` 被当远程主机),容器内解包后 `chown -R root:root`(Windows 的 uid 映射不过来)。
- 镜像上这套 8088 保留着,给 W4 现场演示与操作说明走查用;不用了 `systemctl disable --now nginx` 即可,不影响 TB / kz。

## 4. 同一批改动:向导「记住登录」→「记住账号」

`Provisioner.vue`:localStorage `gridops_login_<env>` 改存明文 JSON `{u, ts}`,不再存密码;读到旧格式(base64,含 `p`)时只取账号并立即用新格式覆盖。预览里验证:预置一条旧格式条目 → 刷新 → 账号栏回填、密码栏为空、存储已改写为 `{"u":…,"ts":…}`、勾选框保持勾选、文案改为「记住账号(30 天,只记账号名不记密码,保存在本机浏览器)」。操作说明、部署指南 v2 安全表、复核记录同步。
