# 独立大屏的长会话(token 续期)· 2026-09-09

补的是外部审查(`codex-scada-deploy-tool-review-2026-09-08.md` §4.1)点出的
「长期会话尚未闭环」。审查当时明说没测真实 token 有效期、不把它伪装成 live 复现;
这次把有效期实测了,也把整条链路端到端验了。

## 1. 原来的问题

`StandaloneApp.vue` 登录时只存 access token,建数据源时给的是一个**定值**:

```ts
source.value = new LegacyDataSource({ baseUrl: s.base, getToken: () => s.token })  // 旧
```

`LegacyDataSource` 不负责刷新(契约里 token 就是归宿主管的,同事的 `TbClient` 也一样),
所以 token 一过期,大屏只能等着挂:REST 401 直接回登录页,WS 重连也只会拿同一张废票。
现场大屏是挂墙长开的,这件事迟早会碰上。

## 2. 先把 TB 的实际行为量出来(镜像,2026-09-09)

| 项 | 实测 |
|---|---|
| `/api/auth/login` 返回 | `{ token, refreshToken }` —— refreshToken 一直有,只是原来没存 |
| access token 有效期 | **2.5 小时**(9000 秒) |
| refresh token 有效期 | **7 天** |
| `POST /api/auth/token { refreshToken }` | 200,回**一对全新的** token(access 和 refresh 都换) |
| 新 refresh token 的窗口 | **滚动**:`iat`/`exp` 从刷新那一刻重新起算(隔 4 秒刷两次,`iat` 跟着走) |
| 旧 refresh token 刷新后 | **仍可用**,不是一次性的 → 并发刷新不会把自己锁死 |
| 无效 refreshToken | 401 `Invalid username or password` |

> 第一次测「是不是滚动」时三次调用落在同一秒里,`iat` 自然相同,差点得出反向结论。
> 隔开 4 秒重测才看出来是滚动的。

**结论**:只要 7 天内续过一次,大屏就不用重新登录;真正的硬上限是「连续 7 天没能续上」。
密码不落盘是硬约束,所以做不到无限免登录,这是能做到的最好结果。

## 3. 改了什么

**新增 `apps/deploy-tool/src/standalone/session.ts`**(纯逻辑,可单测):

- `expOf(token)` —— 读 JWT 的 `exp`;解不出来一律当作已过期(宁可多刷一次,也不要拿废票去请求)。
- `TokenKeeper.freshToken()` —— 距到期不足 60 秒就先换(提前量避开时钟偏差与请求耗时)。
  **并发调用共用同一次刷新**:REST 与 WS 重连可能同时来。
- 刷新成功时**把新的 refreshToken 一起存下** —— 滚动窗口就是靠这一步续的,只存 access token 等于白改。
- 401/403 → 通知调用方回登录页并说清原因;**网络不通不算登录失效**,只抛错不踢人。

**`StandaloneApp.vue`**:

- `Session` 加 `refreshToken`,登录时存下。
- 数据源改成 `getToken: () => freshToken()`。这一处是关键:`LegacyDataSource` 每次 REST 请求
  (`legacy-adapter.ts:266 / 355`)和**每次 WS 重连**(`:443`)都会重新调 `getToken`,所以
  续期逻辑放在这一层就够,**适配器本身一行都不用改,同事的 `TbClient` 将来也一样**(她也是 `await this.getToken()`)。
- REST 收到 401 时:先强制刷一次再重试,仍不行才回登录页(应对时钟偏差 / TB 换过签名密钥 / 会话被吊销)。
- **5 分钟心跳**:大屏数据全走 WS,可能几小时一个 REST 请求都没有;没有心跳的话滚动窗口
  就靠不住了,第 8 天照样掉登录。
- 恢复会话(刷新页面 / 重开标签)先续期再校验,不再因为「access token 过期了」就让人重登一遍。
- 顺带:点「退出」时同时调 `POST /api/auth/logout` 把服务端会话也作废。原来只清本地状态,
  refresh token 在 TB 上还活 7 天,值班室点了退出等于没退干净。

## 4. 验收

**单测** `apps/deploy-tool/test/standalone-session.test.ts` 10 条:`expOf` 各种坏输入;
没到期不刷;快到期刷且新 refreshToken 存下;已过期也能刷;并发只发一次请求;
401 通知过期且原因带「7 天」;网络不通不踢人;缺 refreshToken / 未登录明确报错;
返回体缺字段不写进会话;`reset()` 之后不复用在途刷新。

**端到端**(site.html 对镜像,CUSTOMER_USER `xrs-viewer`,浏览器实跑):

| 场景 | 造法 | 结果 |
|---|---|---|
| access 已过期、refresh 有效 | 会话里塞一张 `exp` 在一小时前的 access token | **直接进页面列表(3 张页面),没回登录页**;会话里的 access 与 refresh 都换成了新的 |
| `exp` 没到但 TB 不认 | 塞一张 `exp` 在一小时后、签名是坏的 token | 401 → 强制刷新 → 重试 → **进页面列表(3 张)**,token 已换 |
| refresh 也废了 | 两张都塞坏的 | 回登录页,提示「**登录已过期(超过 7 天未续期或已被吊销),请重新登录**」 |

第二个场景第一次是**没过**的:恢复会话那条路径当时是裸 `fetch`,碰到 401 直接回登录页,
绕过了 `api()` 的刷新重试。改成走 `api()` 之后才通——这条是实跑查出来的,单测里没覆盖到。

全量:compiler 102 / tb-client 19 / renderer 46 / deploy-tool 82(+10),类型检查、
lint、格式检查全过。

## 5. 遗留

- **`sessionStorage` 不跨标签页 / 不跨浏览器重启。** 关掉标签就要重新登录。这是 T3.8 当初
  为了「凭据不落盘」有意选的,换 `localStorage` 是个安全取舍,**没动,要动得单独定**。
  对挂墙大屏(开着不关)没有影响;对「早上开机打开浏览器」的用法有影响。
- **硬上限仍是 7 天没能续上**(断网一周、机器关机一周)。要突破只能存凭据,与「密码不落盘」
  冲突,不做。
- 编辑器预览(`PreviewPane.vue`)没做续期。它是人在跟前操作的短会话,过期了重新连一次即可,
  不是同一类问题。

## 6. 一处操作失误(已处理)

端到端验证的脚本第一版把会话里的 token 整串打印了出来,两组真实的 access + refresh token
因此进了运行日志。发现后立刻用 `POST /api/auth/logout` 注销了那两个会话,并逐一复核:
两张 access 与两张 refresh 全部返回 401,已失效。脚本随后改成只回 8 位指纹用于比对,
不再输出 token 本体。**没有任何 token 进入仓库或文档。**
